# 测试环境升级指引（0821，v1.5.1 → v1.6.0）

> **面向**：测试服务器的开发维护人员
> **背景**：2026-08-21 生产环境迁移到新服务器（`openlife.beyondego.me`，跑 v1.6.0），详见 `0821-迁移计划-v1.5.1-to-v1.6.0.md`
> **本文档定位**：测试环境**不参与数据迁移**——生产与测试数据本就独立、不同步，生产搬家不影响测试环境的任何数据。你需要做的只是**把测试环境代码升级到 v1.6.0 并保证可正常开发调试**
> **预计耗时**：20~30 分钟

---

## 0. 一句话结论

**数据不用动**（`data/test/`、`data/simple/` 里属于测试的码、测试数据库全部保留原样），只需要：拉代码 → 装依赖 → 迁测试库 → 核对 .env → 重启验证。

⚠️ 唯一容易混淆的点：部分迁移脚本（如 `migrate_activation_schema.py`）会同时处理生产和测试两个数据根。在**测试服务器**上执行时，它只会碰到测试数据根，这是正常且安全的；**不要因为"数据不同步"就跳过 schema 迁移脚本**——它迁的是字段结构（schema），不是业务数据。

---

## 1. 升级前须知（和生产迁移的关键差异）

| 事项 | 生产环境 | 测试环境（你要做的） |
|------|---------|---------------------|
| 数据搬运 | 打包 app.db / data / certs / .env 迁新机 | **不需要，数据原地不动** |
| 域名 | 切到 `openlife.beyondego.me` | **不变**，继续用测试域名 |
| DeepSeek key | 生产 key 放 .env.prod | **测试 key 放 .env**（08-19 起测试/生产 key 完全隔离，测试环境永远不要用生产 key） |
| SECRET_KEY | 沿用旧值 | 沿用测试环境自己的值，**别和生产对齐** |
| 支付宝 | 正式网关 + 真密钥 | 维持沙箱/未配置即可（未配置时下单接口 503，不影响其他功能） |
| 维护模式 / nginx / DNS | 需要配置 | **不用动** |

### Step 1：拉代码切版本

```bash
cd /home/gitclone/BeingDoing
```

### Step 2：装依赖（有新增，不可跳过）

```bash
"$PYBIN/pip" install -r src/backend/requirements.txt
```

>   google-noto-sans-cjk-ttc-fonts

> 不测 PDF 生成功能的话可以不装，其他功能不受影响。

### Step 4：激活码 schema 迁移（测试数据根也要跑）

```bash
cd /home/gitclone/BeingDoing
./start.sh stop    # 脚本要求停服执行（检测 8000 端口）

# 预检（只读）：会同时列出生产/测试两个数据根的待补记录数；
# 测试机上生产根通常不存在或为空，跳过属正常

# 执行（自动备份到 data/backups/，幂等可重跑）
python3 scripts/migrate_activation_schema.py

# 验证：预期「缺字段 0、非法值 无」
python3 -c "
import json
for f in ['data/simple/activations.json', 'data/test/simple/activations.json']:
    try:
        raw = json.load(open(f))
        missing = [c for c, d in raw.items() if 'code_type' not in d]
        bad = {c: d.get('code_type') for c, d in raw.items() if d.get('code_type') not in ('trial', 'full')}
```

## 3. 常见问题

**Q：生产迁移后，测试环境要同步生产数据吗？**
不需要。生产和测试数据从来就不同步，各用各的。测试继续用自己的测试码/沙箱码（SBX/ADM 前缀）即可。

**Q：生产的激活码/用户数据会出现在我的测试库里吗？**
不会。生产数据只去了新生产服务器，没有经过任何共享通道。

**Q：我本地/测试机上 data/simple/ 里有以前拷贝的生产数据怎么办？**
那是历史快照，本次迁移不影响它。如不再需要可以自行清理（别动 `.duplicate/`、`data_backup_*/` 等带日期的归档，那是刻意保留的历史快照）。

**Q：支付宝支付在测试环境怎么测？**
沙箱联调见 `0723-支付宝配置操作文档.md`；不配密钥时下单接口返回 503，属预期行为，不影响其他开发。

**Q：xunlu 渲染引擎（新报告 PDF 渲染器）测试环境要装吗？**
可选。默认引擎 weasyprint 开箱即用；要测 xunlu 需本机有 Node ≥20 + Chrome/Chromium，然后设 `RENDER_ENGINE=xunlu` 或在 admin 报告页运行时切换。详见 ADR-0019。

**Q：升级后测试环境报错了去哪查？**
先看 `./start.sh attach` 的 backend 窗口日志；迁移类问题对照 `0821-迁移计划-v1.5.1-to-v1.6.0.md` 的 §4 坑位清单和 Step 12 回滚方案（测试环境同样适用，回滚 = 恢复 `app.db.bak-before-019` + 恢复 `data/backups/` 里的激活码备份）。
