# 0823 提交即审核 + 报告页下载/异常态改造

> 日期：2026-08-23 ｜ 关联 issue：GitHub #83（记录）｜ 前置相关：#80（报告复核体系）、#79（v4 终选 n选3 UI）、#82（v4 判定修复）
> 方案经 grill-me 访谈定稿，本文记录分析原因与改动口径。

## 一、问题背景与分析原因

用户对「rumination v4 终选（n选3）提交后」的链路提出三点预期，逐条核对代码后发现**现状与预期全部存在偏差**：

### 1. 审核计时锚点错误：提交 ≠ 开始审核

**预期**：n选3 提交完成 → 后台直接开始生成报告，页面进入「审核中（3-24 小时）」。

**实际**：`POST /simple-chat/rumination-v4/final-selection/submit`（`rumination_v4_routes.py`）只做三件事：

1. `submit_final_selection`：写 `final_selection.submitted=True`；
2. `ReportRegistry.lock_step(rid, "rumination")`：五阶段完成度拼图的最后一块；
3. 审计日志。

**不开始审核计时、不触发报告生成、不动 review_status**。审核计时锚点在「用户首次进入报告页」——`export.py` 的 `_ensure_review_started`（由 `GET /export/my-report-id` 触发）才把 `not_started → pending_review`（随机 3~24h deadline）并后台预生成 markdown。

**后果**：用户提交后如果从不主动进报告页，审核永远不开始、报告永远不生成，record 永远卡在 `not_started`。

### 2. 用户侧仍有「生成报告」按钮

**预期**：用户不具备生成报告的选择权。

**实际**：view 页在 approved 且无缓存时显示「生成报告」兜底按钮（`handleGenerate → prepare → POST /export/report-pdf/{id}`）。已下线的只是「重新生成」（2026-08-18，#80），首次生成的兜底入口仍在。

### 3. 下载按钮无反馈、异常态无警示

**预期**：md 缺失时按钮显示「报告异常」警示；点击下载后按钮变「下载中」。

**实际**：`saveNow`（`useReportPdfDownload.ts`）全程不改状态，按钮无 disabled/spinner，可重复点击触发多次下载；md 缺失/下载失败只显示一行红色小字，无警示块。

## 二、决策记录（grill-me 访谈结论）

| # | 决策点 | 结论 |
|---|--------|------|
| 1 | 审核计时 + 预生成触发点 | **前移到 n选3 提交成功时**；进报告页的 `_ensure_review_started` 保留作存量 not_started 懒触发兜底 |
| 2 | 存量「已提交但从未进报告页」的用户 | **不回填**，靠懒触发自然覆盖（不回来的用户本来也不急着看报告） |
| 3 | 「生成报告」兜底按钮 | **下线**；仅在生成失败（`status==='error'`）时保留「重新尝试生成」自救路径 |
| 4 | approved 但 md 缺失/失败时的 UI | **统一警示块**：失败 → 「重新尝试生成」主按钮 +「申请复核」次按钮；无缓存从未生成 → 「报告异常」+ 仅「申请复核」 |
| 5 | 下载按钮 | 加「下载中…」loading 态（disabled + spinner），防重复点击 |
| 6 | 不动的部分 | 审核中全页占位、3~24h 随机超时自动批复（每 10 分钟 job）、批复时 `kick_report_generation` 兜底、站内信通知、复核体系（#80） |

## 三、改动清单

### 后端

- `app/api/v1/rumination_v4_routes.py` — `submit_final_selection_endpoint`：`lock_step` 后重新读 record，复用 `_ensure_review_started` 立即开始审核计时 + 后台预生成 markdown；整段 try/except 包裹，失败仅 log 不影响提交响应（审核计时会在用户进报告页时由懒触发补上）。
  - record 必然存在：`_resolve_v4_ctx_with_rec → resolve_report_context → registry.ensure_report`。
  - 幂等：`start_review` 只作用于 `not_started`；预生成有 `try_acquire_generation` 单轨锁 + `_pdf_tasks` pending 去重。
  - admin 调试沙箱不做特殊处理（admin 本就豁免审核阻塞）。
- `app/utils/report_review.py` / `app/api/v1/export.py` — docstring 同步新锚点口径。

### 前端

- `src/frontend/hooks/useReportPdfDownload.ts` — 新增 `downloading` 状态；`saveNow` 全程置位（finally 复位）+ 重入防御。
- `src/frontend/app/(main)/explore/report/view/page.tsx` —
  - 「下载 PDF 报告」按钮：`downloading` 时 disabled + spinner +「下载中…」；
  - 删除「生成报告」按钮，非 ready 分支重写：生成中（维持原样）/ 失败警示块 / 「报告异常」警示块；
  - 新增 `statusChecked`：approved 后首次 `check` 返回前不渲染异常块，避免 `idle` 闪现误报；reportId 切换时重置。

### 测试与文档

- `test/backend/test_report_review.py` — 新增 `test_review_starts_on_v4_final_submit`：断言提交后 rumination locked + `pending_review` + deadline 落在 3~24h + 预生成任务已启动。
- `AGENTS.md` — 审核计时锚点、生成按钮下线、下载中态口径同步。
- 本文档。

## 四、验证结果

- 后端 `pytest test/backend/test_report_review.py test/backend/test_report_registry.py`：**37 passed**（含新增 1 个）。
- 前端 `npm run build`：编译通过（tsc 无类型错误）。

## 五、遗留与边界

- **v3 老链路未接入提交即触发**：v3 step7 定稿锁 rumination 时不触发审核/预生成，仍靠进报告页懒触发。如需对齐另行开工。
- 存量 not_started 用户不回填（决策 2）。
- 审核通过仍无主动推送：用户靠站内信红点 + 重新进入/刷新页面获知，本次未加轮询。
- 上线口径：纯代码更新，无迁移、无新依赖、无新环境变量；重启后端 + 前端重新 build 即可。
