## 步骤 4：配置 IMAP（关键，没配扫描跑不起来）

### 4.1 开启 163 邮箱 IMAP 服务

1. 浏览器登录 https://mail.163.com → `soulhappylab@163.com`
2. 顶部菜单 → **设置** → **POP3/SMTP/IMAP**
3. 找到 **IMAP/SMTP 服务** → 点 **开启**
4. 按提示用绑定手机发送短信验证
5. **生成客户端授权码**（如果你之前为 SMTP 已经生成过，复用同一个授权码即可）
   - 授权码是 16 位字符串，**不是邮箱登录密码**
   - 复制保存好，关掉页面就看不到了

### 4.2 写入 .env

编辑 `/home/gitclone/BeingDoing/.env`，找到 `BOUNCE_IMAP_*` 段：

```bash
# SMTP 配置（已存在，确认 SMTP_PASS 是授权码即可）
SMTP_HOST=smtp.163.com
SMTP_PORT=465
SMTP_USER=soulhappylab@163.com
SMTP_PASS=<你已有的 16 位授权码>

# 退信扫描 IMAP 配置
BOUNCE_IMAP_HOST=imap.163.com
BOUNCE_IMAP_PORT=993
# 这两个留空 = 自动复用 SMTP_USER / SMTP_PASS
# 163 邮箱的 IMAP 和 SMTP 共用同一个授权码，留空即可
BOUNCE_IMAP_USER=
BOUNCE_IMAP_PASS=
```

### 4.3 重启后端让配置生效

```bash
./start.sh restart backend
```

### 4.4 验证 IMAP 连通性

```bash
TOKEN="<your_admin_access_token>"
curl -X POST https://career.soulhappylab.com/api/v1/admin/bounces/scan \
  -H "Authorization: Bearer $TOKEN"
# 期望：
#   {
#     "scanned": N,
#     "candidates": N,
#     "parsed": N,
#     "added": N,
#     "unparsed": N,
#     "last_uid": N,
#     "error": null    ← error 必须是 null 才算 IMAP 通了
#   }
```

错误对照：
- `[AUTHENTICATIONFAILED]` → 授权码错或 IMAP 没开
- `[Connection refused]` → 网络问题或 host/port 错

## 步骤 5：上线后日常

### 5.1 自动扫描

- **每日 03:00（北京时间）** 自动触发
- 在 tmux backend 窗口看日志：`INFO: bounce scan done: {...}`
- 错过一次无所谓：lookback 48 小时兜底

### 5.2 手动扫描

- 前端 → 通知邮件群发 → 退信黑名单 tab → "立即扫描退信"按钮
- 或 curl：`POST /api/v1/admin/bounces/scan`

### 5.3 群发联动

- 创建群发任务时，**自动跳过** `email_bounces.status='blocked'` 的邮箱
- 无论"条件筛选"还是"手动勾选"，都会过滤
- 若要给某黑名单邮箱发信：先在黑名单 tab 点"解封" → 再群发

### 5.4 监控建议

- 每周看一次 `/admin/bounces/stats`
- `blocked_total` 异常增长 → 发信质量下降
- 黑名单超过 1000 条后建议定期 review

## 回滚方案（万一升级失败）

### 完整回滚（DB + 代码）

```bash
cd /home/gitclone/BeingDoing/src/backend

# 1. DB 退回 005
alembic downgrade 005_fix_timestamps_tz
# 这会执行 006 的 downgrade：DROP TABLE email_bounces

# 2. 验证
alembic current
# 期望：005_fix_timestamps_tz (head)

# 3. 如果 downgrade 也失败，恢复备份
cd /home/gitclone/BeingDoing
cp src/backend/app.db.bak.20260702 src/backend/app.db

# 4. 代码回滚
git revert <这次提交的 hash>

# 5. 重启
./start.sh stop && ./start.sh start prod
```

### 仅禁用扫描（保留 DB）

```bash
# 编辑 .env，把 cron 改成不触发的时刻
BOUNCE_SCAN_CRON=0 0 1 1 *

./start.sh restart backend
```

## 排错速查

| 现象 | 原因 | 解决 |
|------|------|------|
| `alembic upgrade` 报 `Can't locate revision` | revision 链断了 | 检查 006 的 `down_revision` 是否 = `005_fix_timestamps_tz` |
| 启动报 `No module named 'apscheduler'` | 依赖没装 | `pip install apscheduler>=3.10.0` |
| 启动报 `No module named 'app.services.bounce_scanner'` | 文件路径错 | 确认 `src/backend/app/services/bounce_scanner.py` 存在 |
| 扫描返回 `error: "IMAP 未配置..."` | `.env` 没填或没重启 | 步骤 4 |
| 扫描返回 `error: "AUTHENTICATIONFAILED"` | 授权码错或 IMAP 没开 | 步骤 4.1 重新生成授权码 |
| 黑名单 tab 看不到 / 404 | 前端没重新 build | `./start.sh stop && ./start.sh start prod`，然后 Ctrl+Shift+R |
| 群发时还是给黑名单邮箱发了 | DB 没升级到 006，或 admin 走了别的路径 | 确认 `alembic current` = 006 |

## 关键决策记录

1. **加新表 vs 文件存储**：选加表。长期资产、查询性能、并发安全、审计需要
2. **hard vs soft**：hard（550）直接 blocked；soft（邮箱满等）累计 3 次才 blocked
3. **解封后是否自动重 block**：是。下次扫到新退信，hard 立刻重 block，soft 继续累计。无冷却期
4. **扫描失败重试**：不重试。lookback 48h 兜底，下次 cron 追上
5. **手动勾选 vs 条件筛选的黑名单过滤**：两种模式都过滤。要发黑名单邮箱必须先解封
6. **IMAP 授权码与 SMTP 共用**：是。163 同一授权码通用，`BOUNCE_IMAP_USER/PASS` 留空即可
7. **timezone**：APScheduler 用 `Asia/Shanghai`，`BOUNCE_SCAN_CRON` 是本地时间（北京时间）
