## 启用 v4 的方式(前端)

v3 行为默认不变。启用 v4 有两种方式:

1. **URL 参数(临时)**:访问 `https://your-domain/explore/chat/rumination?v4=1`
2. **localStorage(持久)**:浏览器控制台执行 `localStorage.setItem('rumination_v4', '1')`,之后访问 rumination 即走 v4

> 启用 v4 后,用户一进入 rumination 就是矩阵页;不启用则保持原 v3 七步流。

所有端点前缀 `/api/v1/simple-chat/rumination-v4`:

| 方法 | 路径 | 用途 |
|---|---|---|
| GET | `/state` | 全局 v4 state |

| POST | `/start-discussion` | 开始讨论(组合固定,返回开场消息) |
| POST | `/combo-chat` | 主对话(SSE 流式) |
| DELETE | `/combos/{combo_id}` | 硬删除 |
| PATCH | `/combos/{combo_id}/conclusion-card` | 用户直接编辑结论卡 |
| POST | `/combos/{combo_id}/status` | 确认/放弃 combo |
| POST | `/final-selection` | 第 8 步:选定 1-3 个 |
| POST | `/final-selection/submit` | 第 8 步:锁定提交 |
| POST | `/active` | 切换 active combo |

## 兜底机制(双信号)

LLM 生成结论卡时必须输出两个信号:
- 隐藏标记:`<<CONCLUSION_READY>>`(后端正则匹配,前端过滤)
- 用户可见话术:`现在我为你总结了 N 个假设,你可以选择其中一个`

后端监测逻辑:
- 两个信号都有 → 正常出卡
- **有 visible 但无 hidden** → LLM 忘了 → 用独立 conclusion prompt + 摘要重新生成 → SSE 推送
- 有 hidden 无 visible → 异常告警
- 都没有 → 不触发

## 联调验证步骤

1. 启动后端:`./start.sh restart backend`
2. 启动前端:`./start.sh restart frontend`
3. 浏览器登录,访问 `/explore/chat/rumination?v4=1`
4. 矩阵页选热爱+优势 → 确认创建 → 进入对话 → 点开始讨论 → 对话若干轮 → 等待 LLM 出卡(或触发兜底)→ 编辑卡 → 确认 → 顶部点"最终选择" → 选 1-3 个 → 提交
5. 创建第二个组合(相同子集,验证允许重复)→ 切换 tag → 删除 combo(二次确认)

## 已知限制

- **tool call 用文本协议(```tool``` 隐藏块),非 OpenAI 原生 function calling**:原因见 base.py 的 LLMMessage 不支持 tool_calls 字段,且项目已有成熟的隐藏 JSON 块解析模式(stream_utils.py)。
- **结论卡生成依赖 LLM 可靠性**:兜底机制覆盖"忘输出标记"场景,但若 LLM 完全不调 save_conclusion_card 且无 visible 话术,需用户主动"放弃"。
- **30 轮摘要阈值固定**:暂未做动态调整,可后续按 token 数触发。
