# 域名收敛与 SEO 执行手册（2026-09-17）

> **要解决什么**：搜索引擎能搜到测试环境（career.*）和裸 IP:端口（3000/8000）页面；soulhappylab.com 旧品牌域名与 beyondego.me 并存，权重被稀释。
> **最终目标**：
> ① 搜索引擎只收录 `openlife.beyondego.me`；
> ② 测试环境（career.beyondego.me）公众打不开、但团队输密码就能用（真实域名+HTTPS，与生产行为一致）；
> ③ 公网只能走 80/443 经 nginx 访问，IP:端口直连彻底失效。

| beyondego.me（裸域） | prod 机 | 品牌裸域 | 301 → openlife.beyondego.me（可选但建议） |

**两条关键事实（操作前必读）：**

1. **访问链路**：用户 → 域名 → nginx(443) → 127.0.0.1:3000(前端) / 127.0.0.1:8000(后端)。nginx 和应用在**同一台机器**，走本机回环。所以 3000/8000 绑到 127.0.0.1 后，域名访问**完全不受影响**，但 `http://IP:3000` 直连会彻底失效——这正是我们要的。
2. **Basic Auth 的坑**：前端调 `/api/` 时会带 `Authorization: Bearer <JWT>` 头，和 Basic Auth 用的 `Authorization: Basic` **冲突**。所以密码只加在页面路径（`location /`），**`/api/` 必须豁免**——API 本身有 JWT 鉴权，返回 JSON 也不会被搜索引擎收录，不影响隐藏效果。

## 1. Dev 机操作（47.96.75.69，本机）

### 1.1 阿里云安全组封端口 ⭐ 最优先

- **为什么**：搜索引擎收录的 `http://47.96.75.69:3000` 这类页面，根因是安全组放行了 3000/8000。封掉后公网直连立即死亡，已收录页面会变成超时，几周后被搜索引擎清除。
- **怎么做**：阿里云控制台 → ECS → 找到 47.96.75.69 实例 → 安全组 → 配置规则 → **入方向**：删除/禁用 3000、8000 的规则。最终只保留 `80`、`443`、`22`（22 建议把授权对象从 0.0.0.0/0 改成你当前 IP/32；另外把 1Panel 面板端口的规则也限制为你的 IP）。
- **做完什么样**：`curl -m 5 http://47.96.75.69:3000/` 超时拒连；`https://career.beyondego.me` 域名访问**完全正常**（走 nginx 443）。

### 1.2 重启服务，让 127.0.0.1 绑定生效

- **为什么**：代码已改好（start.sh 的 uvicorn、package.json 的 next 都绑 127.0.0.1），这是双保险——即使哪天安全组被误开，端口也只在回环上。
- **怎么做**：
  ```bash
  cd /home/gitclone/BeingDoing && ./start.sh restart
  ss -tlnp | grep -E ':3000|:8000'
  ```
- **做完什么样**：两行都显示 `127.0.0.1:3000` / `127.0.0.1:8000`（不再是 0.0.0.0）；career.beyondego.me 照常能用。

### 1.3 career.beyondego.me 加 Basic Auth（核心隐藏手段）

- **为什么**：爬虫过不了密码框，拿到 401 就走，页面一个字都看不到，自然不会收录；团队成员浏览器输一次密码即可正常用。真实域名+真实 HTTPS，Cookie/CORS 行为和生产一致，比 localhost 映射靠谱。
- **怎么做**：
  ① 生成密码文件（在 dev 机执行；注意 1Panel 的 nginx 在 docker 容器里，宿主机 `/opt/1panel/apps/openresty/openresty/www` 映射为容器内 `/www`）：
  ```bash
  printf "team:$(openssl passwd -apr1 '换成你的强密码')\n" \
    > /opt/1panel/apps/openresty/openresty/www/sites/career.beyondego.me/.htpasswd
  ```
  ② 1Panel → 网站 → career.beyondego.me → 配置文件，做三处修改：
  - 在 `location / {` 块内**最前面**加两行：
    ```nginx
    auth_basic "internal";
    auth_basic_user_file /www/sites/career.beyondego.me/.htpasswd;
    add_header X-Robots-Tag "noindex, nofollow" always;
    ```
  - 在 `location ^~ /api/ {` 块内加一行（**必须，否则登录后接口全 401**）：
    ```nginx
    auth_basic off;
    ```
  - 在 `location ^~ /_next/static/ {` 块内加一行（静态资源豁免，避免浏览器重复弹窗）：
    ```nginx
    auth_basic off;
    ```
  - 在 server 块任意位置加一段（让爬虫能读到明确的"全站禁止"，加速旧收录消亡）：
    ```nginx
    location = /robots.txt {
        auth_basic off;
        default_type text/plain;
        return 200 "User-agent: *\nDisallow: /\n";
    }
    ```
  ③ 重载生效：
  ```bash
  docker exec 1Panel-openresty-hjWm nginx -t && docker exec 1Panel-openresty-hjWm nginx -s reload
  ```
- **做完什么样**（逐条验证）：
  ```bash
  curl -I https://career.beyondego.me/                              # 期望 401
  curl -I -u team:'你的强密码' https://career.beyondego.me/          # 期望 200
  curl https://career.beyondego.me/robots.txt                       # 期望 200 + Disallow: /
  ```
  浏览器打开 career.beyondego.me → 弹原生密码框 → 输入后能正常登录、聊天、调接口（API 走 Bearer 不受 Basic Auth 影响）。

### 1.4 dev 机上的 soulhappylab 旧域名收口

- **为什么**：`soulhappylab.com`、`admin.soulhappylab.com`、`career.soulhappylab.com` 都解析到 dev 机（zhiyinapp.conf 和 admin conf 在服务它们）。301 把权重导给正主，也让搜到旧链接的用户落到新站。
- **怎么做**（1Panel 网站列表里操作，或直接改 conf.d 文件）：
  - **zhiyinapp 站**（server_name 含 soulhappylab.com / www.soulhappylab.com / career.soulhappylab.com）：
    把 `career.soulhappylab.com` 从 server_name 里**删掉**（它要单独处理），然后把剩下的 server 块改成纯 301——在 server 块内加：
    ```nginx
    if ($host != "career.soulhappylab.com") {
        return 301 https://openlife.beyondego.me$request_uri;
    }
    ```
    > 更干净的做法：把 zhiyinapp.conf 里的 `soulhappylab.com www.soulhappylab.com` 整个 server 改成只含 `return 301 https://openlife.beyondego.me$request_uri;`（证书配置保留）。career.soulhappylab.com 单独建一个站点：`return 301 https://career.beyondego.me$request_uri;`。
  - **admin.soulhappylab.com 站**：整站 `return 301 https://openlife.beyondego.me$request_uri;`（admin 功能现在走 openlife.beyondego.me/admin 路径）。
  - ⚠️ **三个域名的 HTTPS 证书都要保留并续期至少 6-12 个月**——证书过期则 301 在 TLS 握手时就死了，权重转移中断。
- **做完什么样**：
  ```bash
  curl -I https://soulhappylab.com/            # 301 → openlife.beyondego.me
  curl -I https://admin.soulhappylab.com/      # 301 → openlife.beyondego.me
  curl -I https://career.soulhappylab.com/     # 301 → career.beyondego.me
  ```

## 6. 故障回退

- Basic Auth 配错导致团队进不去：删掉那两行 auth_basic → reload nginx 即恢复。
- 301 配错：`nginx -t` 不通过就不会生效，改回去 reload 即可。
- 封端口后有任何功能异常（不应该有，nginx 反代不经过公网）：阿里云控制台把规则加回来即可，秒级恢复。
