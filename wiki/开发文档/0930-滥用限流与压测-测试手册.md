## 4. 手工 E2E 验证（浏览器，需要 dev 环境运行中）

前置：`./start.sh dev` 起服务，准备一个超管账号 + 一个普通测试账号。

### 4.1 警告→冻结→解冻全流程（10 分钟）

1. **调低阈值**：超管登录 → admin → 滥用监控 → 把 `msg_per_minute` 改成 `2` → 保存
2. **触发警告**：普通账号进 values 阶段聊天，1 分钟内连发 3 条消息
   - 预期：第 3 条被拒绝，输入框上方出现琥珀色警告条「操作过于频繁…」
3. **触发冻结**：继续再发 1 条
   - 预期：弹出红色冻结弹层「账号存在异常操作，聊天功能已冻结」，输入框禁用；
     该用户收到站内信（`abuse_frozen`）+ 邮件；超管收到站内信（`abuse_frozen_admin`）
4. **确认码被 revoke**：admin → 激活码管理 → 找到该用户的码，状态为 revoked
5. **解冻**：admin → 滥用监控 → 已冻结 tab → 「解冻恢复」→ 确认
   - 预期：用户收到 `abuse_unfrozen` 站内信；回 chat 页发消息恢复正常；激活码回 active
6. **恢复阈值**：把 `msg_per_minute` 改回 `10`

### 4.2 只读不受限验证

冻结状态下：刷新页面、查看历史对话、查看报告——全部正常；只有发消息被 403。

## 5. 并发压测

### 5.1 三步走

```bash
cd /home/gitclone/BeingDoing
PY=/mnt/vdb1/miniconda3/envs/py312/bin/python   # 生产机换成 /root/miniconda3/bin/python

# ① 建压测账号（直连后端内部服务，必须在目标机上跑；60 个号约 10 秒）
$PY scripts/load_test.py --mode setup --users 60

# ② 压测（--base-url 指目标；本地压本地就省略）
$PY scripts/load_test.py --mode run \
  --base-url http://127.0.0.1:8000 \
  --scenario readonly,chat_sse,pdf_render \
  --ladder 1,5,10,20,50 --duration 30 \
  --report-id <一个已完成五阶段的存量报告ID>

# ③ 压完清理（物理删除压测账号+激活码+会话，务必执行）
$PY scripts/load_test.py --mode teardown
```

### 5.2 场景说明与成本控制

| 场景 | 内容 | token 成本 |
|---|---|---|
| `readonly` | 登录 → journeys → 聊天历史，循环打 | **0** |
| `chat_sse` | init → 2-3 条极短消息（「你好」级），完整消费 SSE | 几块钱内（受 `--max-chat-messages` 保险丝控制，默认 500 条） |
| `pdf_render` | 存量报告并发渲染 PDF，**并发硬上限 3** | 0（纯 CPU） |

### 5.3 压前必做：关掉滥用限流

否则压测账号会被正常工作的限流系统冻结：

- admin → 滥用监控 → `enabled` 置 false（压完恢复 true）
- 或命令行：`echo '{"enabled": false}' > data/abuse_config.json`

### 5.4 结果解读

产物在 `scripts/` 下：`load_test_result_<时间戳>.json`（原始数据）+ `load_test_report_<时间戳>.md`（表格报告）。

```
[readonly] 并发=5   请求=733  失败=0  错误率=0.0% 吞吐=90.75 req/s | p50=51.1ms p95=72.8ms
[chat_sse] 并发=3   请求=14   失败=0  错误率=0.0% 吞吐=0.94 req/s  | p50=2719ms | TTFT p50 74ms
```

判断标准（Markdown 报告会自动标注）：
- **错误率 > 1%** 的档位 = 系统瓶颈档位
- **p95 随并发陡增**（如 10 并发正常、20 并发翻倍）= 拐点在两者之间
- chat_sse 关注 **TTFT**（首 token 延迟，用户体验指标）和总耗时（模型生成速度，主要受 DeepSeek API 限制）
- readonly 的吞吐是服务器天花板参考；chat_sse 吞吐低是正常的（LLM 生成慢）

### 5.5 常见问题

| 现象 | 原因 | 处理 |
|---|---|---|
| 登录 422 | 账号邮箱域名不合法 | 别改 `LOADTEST_EMAIL_DOMAIN`（`.local` 过不了 EmailStr） |
| 登录 423 | 触发防爆破锁定 | 脚本已有 0.5s 退避；出现说明密码错了，检查 accounts 文件 |
| chat_sse 大量 402 | 试用码 10 轮上限 | 正常，worker 会优雅退出；加账号数或减少每号消息数 |
| pdf_render 全 403 | 报告不归属压测账号 | 换归属压测账号的 report-id，或用超管账号 |
| setup 报 `no such column` | 连错了库/迁移没跑 | 脚本已自动 chdir 到 src/backend；确认该环境 `alembic upgrade head` 已跑 |
