# OpenLife UI 设计系统

> 版本：1.0  
> 设计主题：**Quiet Clarity / 静谧探索**  
> 适用范围：首页、职业探索对话、Rumination 工作台、报告、个人空间、购买弹窗、帮助与协议等后续页面

## 1. 我们要创造什么感觉

OpenLife 不是效率后台，也不是娱乐化测评。它是一处帮助用户慢下来、看清自己、做出选择的数字空间。

理想体验可以归纳为五个词：

- **清新**：高明度纸白底，空气充足，颜色干净。
- **清楚**：三秒内看懂“我在哪里、现在做什么、下一步是什么”。
- **高级**：克制的色彩、准确的排版、统一的边缘与阴影，而不是堆叠效果。
- **温暖**：有轻微生命感、纸张感和自然线条，但不幼稚、不甜腻。
- **沉浸**：内容是中心，背景与动效只在外围缓慢呼吸。

一句话规范：

> **以纸白和深墨建立秩序，用单一阶段色说明语义，用边缘柔光和有节制的自然动效提供情绪。**

### 本规范的优先级

本文件是后续新页面与改版页面的视觉、交互基线。若旧原型或旧说明中的宋体标题、蓝色方形按钮、浅蓝用户气泡等规则与本规范冲突，以本规范为准；业务文案、数据、页面入口和已有功能仍必须保留，除非产品需求明确调整。旧页面可以分阶段迁移，不要求为了“统一”一次性重写稳定功能。

## 2. 八条设计原则

### 2.1 内容先于装饰

每个视口只设置一个视觉焦点。标题、当前任务、主要动作必须先于玻璃、插画、渐变和动效被感知。

### 2.2 中性色承载，主题色导航

页面 80%–88% 由纸白、白色、深墨和灰色构成；8%–15% 可以使用当前阶段的浅色；真正高纯度的阶段色通常不超过 5%。

五色不是“五块大背景”，而是五种语义：阶段、选择、进度、关联结论和少量环境气氛。

### 2.3 一屏一个色彩上下文

除旅程总览和 Rumination 的极淡环境光外，一个页面只允许一个主阶段色。不要在同一屏让蓝、绿、红、黄、紫争夺注意力。

### 2.4 沉浸来自秩序

沉浸感的优先级为：

1. 排版与留白
2. 信息层级
3. 白度差异
4. 细边与阴影
5. 主题色
6. 装饰与动效

### 2.5 玻璃是局部表面，不是全页滤镜

玻璃只用于卡片、浮层、聚焦工作区和弹窗。长正文保持接近纸白。禁止整页罩一块大玻璃，也避免玻璃套玻璃。

### 2.6 动效解释变化，不表演技术

快速动效说明“我选中了、展开了、切换了”；慢速动效只营造呼吸。所有动画都应可被 `prefers-reduced-motion` 安全关闭。

### 2.7 状态不只依赖颜色

选中态同时使用更高白度、主题色边框/短线、轻环和勾选状态。错误、完成、禁用也必须有文字或图形辅助。

### 2.8 文字是真正的界面

这是个人探索产品，正文需要被认真阅读。不要用 9–10px 小字承载说明，不要用装饰性字体制造“高级”，不要在文字背后放具象插画。

## 3. 设计 Token

### 3.1 中性色

| Token | 色值 | 用途 |
|---|---:|---|
| Paper | `#FBFCFB` | 默认页面背景 |
| Paper Cool | `#F7F9FC` | 个人空间、信息页的轻冷背景 |
| Surface | `#FFFFFF` | 阅读面、重要卡片 |
| Ink | `#182130` | 标题、主按钮 |
| Ink Soft | `#293644` | 正文强信息、深色气泡 |
| Body | `#465366` | 正文 |
| Muted | `#5F6C7D` | 次要说明，在近白底保持 AA 对比度 |
| Faint | `#667285` | 最浅文字色，不再叠加透明度 |
| Hairline | `#E3E8EC` | 分割线、默认边框 |
| Control Border | `#84909F` | 输入、选择卡等必须可识别的交互边界 |
| Dark Action | `#222B35` | 默认 CTA、发送、确认 |

### 3.2 五阶段语义色

| 阶段 | Accent | Action | Deep | Soft | Wash |
|---|---:|---:|---:|---:|---:|
| 价值观 | `#5B84E6` | `#3569D4` | `#254F9D` | `#EEF4FF` | `#DCE9FF` |
| 优势 | `#39AE91` | `#147B65` | `#176A57` | `#EDF9F5` | `#D5F0E8` |
| 热爱 | `#E86F7E` | `#C8455A` | `#9E3544` | `#FFF0F2` | `#FFDDE2` |
| 使命 | `#F0B33B` | `#F0B33B` | `#7C520D` | `#FFF7E8` | `#FFE9BA` |
| 沉淀 | `#886DDC` | `#6F52C7` | `#51399F` | `#F3F0FF` | `#E3DCFF` |

使用规则：

- 页面只激活一组 `accent / action / deep / soft / wash`。
- Accent 用于大号编号、线性图标、进度和装饰；小文字、焦点环与关键边界使用对比度更安全的 Deep。
- Action 仅用于明确的阶段动作；默认主动作仍使用深墨色。
- Soft 用于选中卡或结论卡的浅底。
- Wash 只用于低透明度环境柔光。
- 使命阶段的黄色实心按钮使用深色文字 `#20170C`，其余阶段实心按钮使用白字。
- Hairline 只用于装饰性分隔；必须靠边界识别的控件使用 Control Border 或达到 3:1 的 Deep。

### 3.3 字体与层级

推荐字体栈：

```css
font-family: "OpenLifeSans", "Noto Sans SC", Inter, -apple-system,
  BlinkMacSystemFont, "SF Pro Display", "PingFang SC", "Microsoft YaHei",
  system-ui, sans-serif;
```

| 层级 | 建议规格 | 使用场景 |
|---|---|---|
| Hero H1 | 56–82px / 700 / 1.04 | 首页唯一主标题 |
| Page H1 | 36–64px / 680 / 1.12 | 阅读页、报告页 |
| Section H2 | 28–36px / 660 / 1.22 | 大模块标题 |
| Card H3 | 18–22px / 650 / 1.35 | 卡片与工作区标题 |
| Body | 15–17px / 400 / 1.75–1.95 | 说明与阅读正文 |
| Chat | 13–15px / 400 / 1.80–1.95 | 聊天气泡 |
| Kicker | 10–12px / 650 / tracking 0.12–0.20em | 英文或编号提示 |
| Metadata | 11–13px | 时间、状态、帮助信息 |

排版纪律：

- 中文标题使用现代黑体，不使用书法体或装饰性宋体。
- 标题可轻微负字距，正文保持正常字距。
- 长正文宽度控制在 32–42 个中文字符左右。
- 同一页面最多三个清晰文字层级，减少“每行都加粗”。
- 9–10px 仅用于短编号和微型状态，不能作为普通说明文字。

### 3.4 间距、圆角与阴影

- 基础间距单位：8px。
- 页面最大宽度：1280–1320px。
- 桌面左右安全边距：40–64px；移动端 16px。
- 控件圆角：8–12px。
- 选择卡圆角：12–18px。
- 常规卡片圆角：18–22px。
- 大区块圆角：24–34px。
- Pill、tag、主 CTA：999px。

默认柔和阴影：

```css
box-shadow: 0 18px 50px rgba(31, 48, 64, 0.06);
```

浮层阴影：

```css
box-shadow: 0 16px 40px rgba(24, 33, 48, 0.12);
```

阴影不能代替布局。若需要较重阴影才能分清模块，优先重做间距、白度和边框层级。

## 4. 表面、背景与装饰

### 4.1 柔雾玻璃

推荐基线：

```css
background: rgba(255, 255, 255, 0.76);
border: 1px solid rgba(255, 255, 255, 0.90);
backdrop-filter: blur(20px) saturate(116%);
box-shadow:
  0 18px 50px rgba(31, 48, 64, 0.06),
  inset 0 1px rgba(255, 255, 255, 0.96);
```

哑光玻璃依靠“半透明白 + 细边 + 轻阴影”分层；不要加入高光扫过、镜面反射、亮银描边或强烈 3D 效果。

### 4.2 颗粒

- 颗粒是静态纸感，不是可见噪点。
- 首页与 Chat 的全局画布颗粒必须低于 `0.025`；推荐首页 `0.018–0.022`、Chat `0.012–0.02`。
- 只有报告、参考文献和编辑型纸张表面可在自身边界内使用 `0.025–0.04` 的纤维或纸感；普通卡片不重复叠加颗粒。
- 文字区域如出现脏灰感，先降低噪点透明度，再检查渐变是否混入过多互补色。

### 4.3 柔色晕染

- 默认页面仅用当前阶段色的 1–2 团边缘柔光。
- 透明度通常 0.06–0.12，中心必须保持接近纸白。
- Rumination 可出现前四色的极淡回声，但紫色仍是交互锚点。
- 不做整屏五色平均分布，不在正文区域形成明显色块。

### 4.4 细线植物与贴图

- 放在边缘、留白区或固定视觉层，不穿过正文和操作控件。
- `pointer-events: none`，不参与阅读顺序。
- 常规透明度 0.20–0.55；若为核心品牌图可提高到 0.65。
- 线性 SVG 使用 1.3–1.7px 描边；避免 emoji 或不同风格图标混用。
- 首页 Hero 的品牌背景与内容一起正常滚走；Hero 之后可用固定细线植物在屏幕边缘缓慢显现。

## 5. 核心组件规范

### 5.1 顶栏

- 高度约 68px。
- 半透明白 + 12–14px 模糊；滚动后略提高白度和阴影。
- Logo 在左、主导航居中、语言与头像在右。
- 当前页使用 2px 蓝色下划线，不使用整块高饱和 tab。

### 5.2 按钮

主按钮：

- 深墨 pill、白字、44–48px 高。
- Hover 上移 1–2px并略加强阴影。
- Active 缩放至 0.985。
- 一个视图只保留一个最强主动作。

次按钮：

- 透明或白底、细边、深色文字。
- 不与主按钮争夺视觉重量。

阶段色实心按钮只用于含义明确的阶段动作；发送、完成并继续、购买等全局动作优先深墨色。

### 5.3 选择卡

默认态：80%–86% 白、细灰边、极轻阴影。  
Hover：上移 2px、白度提高、边框略接近阶段色。  
选中态：95%–98% 白、阶段 Deep 边框、低透明度外环、明确勾选。  
禁用态：透明度 0.40–0.58，并保留可读说明。

### 5.4 聊天气泡

- AI 默认深墨底、白字；长阅读型回答可以切换为浅色中性面。
- 用户默认纸白底、深字、轻边与轻阴影。
- 气泡圆角使用小切角方向区分：AI `4px 19px 19px 19px`，用户反向。
- 不给每轮消息使用不同颜色；阶段色放在头像、状态线、引用或结论关系上。
- 输入框使用白色浮动 pill，发送按钮使用深墨圆按钮。

### 5.5 结论卡

- 前四阶段结论卡默认展开。
- 背景、标签和边缘从当前阶段 token 派生，不提供四个互不相关的固定色板。
- 内容可以用关键词标签、摘要、解释和下一步动作构成。
- 第五阶段 Rumination 不增加重复“结论汇总”；“我的方向”本身就是结论卡。

### 5.6 参考文献

参考文献使用“干净论文/纸页”语言，而不是普通玻璃卡：

- 近暖白纸色。
- 极淡横纹或纸纹。
- 双层细边。
- 明确的序号、作者、年份、题目、来源和链接层级。
- 支持未来长列表、筛选和折叠，但不牺牲阅读密度。

### 5.7 FAQ

- 默认仅显示问题与分割线，减少大卡片堆叠。
- 展开后才形成白色内容面和极轻阴影。
- 推荐一次只展开一项。
- 原生 `details` 或可访问 accordion，支持键盘与屏幕阅读器。

### 5.8 弹窗与 Popover

- 接近不透明白、20–24px 圆角、24px blur、柔和暗色 backdrop。
- 外观实验、气泡风格、背景选项等非正式功能收进小图标 Popover，不占用主页面空间。
- Esc 关闭；点击外部关闭；打开后焦点进入，关闭后返回触发按钮。

## 6. 页面模式

### 6.1 首页 Landing

首页是一个自然长页面，不是多个路由假装拼接：

1. Hero：品牌标题、slogan、主 CTA、五阶段短卡。
2. 报告预览。
3. 用户评价。
4. 参考文献。
5. 常见问题。
6. 页尾行动与 Footer。

Hero 内的标题、背景图、slogan 和五张卡作为完整首屏一起向上滚走。Hero 之后的细线植物可在页面边缘 fixed，并通过白色光晕过渡淡入；不能遮挡内容。

首页各大内容容器宽度相同或近似，形成稳定纵向节奏。不要让某一模块突然窄很多，除非它是明确的阅读列。

### 6.2 普通 Phase Chat（1–4）

- 对话是主任务，主题色只说明当前阶段。
- 桌面保留现有会话侧栏：新建、切换、当前状态、删除与保存提示属于核心功能契约；平板和手机可将其收进抽屉，但不能删除。
- 顶部保留五阶段选择，但压缩在 `conversation-top` 内，不独占大块高度。
- AI 深色气泡、用户白色气泡、深色发送与“完成并继续”。
- 结论卡默认展开并与阶段色关联。
- 快捷建议不是 1–4 阶段的默认必备项；只有在真实内容策略提供阶段专属建议时才显示。
- 页面使用当前阶段色的轻微动态晕染，不使用五色同时铺满。

### 6.3 Rumination 横向工作台（5）

推荐桌面结构为 47:53：

- 左侧：纯文字的热爱单选与优势多选、方向内容。
- 右侧：对话区。
- 两侧在视觉重量上接近，对话区宽度不应明显不足。
- 五个优势：宽屏一行 5 个；中屏 3+2；手机 2+2+1。
- 热爱选项不使用 emoji；使用文字和统一线性图标（如确有必要）。
- 紫色用于交互锚点；前四色只可成为极淡、流动的边缘光。
- “我的方向”是本阶段唯一结论，不再叠加普通 phase 结论卡。

### 6.4 阅读、报告、关于与协议页

- 保持自然长滚动，禁止套用 Chat 的 `100svh + overflow:hidden`。
- 主阅读列 680–760px；目录或元信息可作为辅助侧栏。
- 背景可以使用单色柔光或同色系撞色晕染，但中心阅读面保持干净。
- 报告和参考文献偏纸张质感；关于我们可使用更完整的边缘品牌图。
- 隐私协议、条款等使用真实标题层级、锚点目录与更新日期。

### 6.5 个人空间

- 桌面左侧约 238px 轻玻璃导航，右侧内容区。
- 当前进度、个人信息、旅程卡之间依靠留白、编号、细边和轨道分区。
- 阶段色用于进度节点和状态，不把整张卡染色。
- ≤1050px 时左侧导航变为顶部横向导航；≤720px 时阶段轨道可横向滚动。

### 6.6 购买弹窗

- 非全屏，居中弹出；主内容与计划选择分栏。
- 仅保留两个购买选项，不出现免费体验。
- 两个方案都明确展示“1 次免费报告复核权限”。
- 比较表默认收起，展开后在弹窗内部或二级层自然滚动。
- 选中方案使用高白度、主题色细边、轻环和勾选，不使用大面积主题色填充。

## 7. 动效系统

### 7.1 时间与缓动

| 类型 | 时长 | 推荐用途 |
|---|---:|---|
| Fast | 140ms | 按压、按钮 hover、图标反馈 |
| Base | 240ms | 选择、tab、气泡出现 |
| Slow | 320–420ms | 面板、弹窗、阶段切换 |
| Ambient | 18–28s | 背景柔光、植物呼吸 |

统一缓动：

```css
cubic-bezier(.2, .8, .2, 1)
```

### 7.2 幅度

- 内容进入：Y 轴 4–8px + opacity。
- 卡片 hover：上移不超过 2px；报告预览可到 6px。
- 按压：`scale(.985)`。
- 环境柔光位移 2%–8%，scale 0.94–1.05。
- 植物偶发摆动 1.5–2°，周期 8–14s，并保留明显静止时间。

### 7.3 背景流动

- 使用 2–3 个大尺度 radial gradient 或模糊 blob。
- 慢速错相移动，中心留白。
- 优先动画 `transform` 和 `opacity`，避免持续改变昂贵的滤镜参数。
- 提供暂停背景动效的入口；`prefers-reduced-motion` 下停用漂移、摇摆和视差。

### 7.4 页面切换与状态变化

- Phase 切换保留草稿和已选择内容。
- Tab/卡片内容切换使用淡入与 4px 位移，不做横向大滑动。
- 新消息出现不应推动用户正在阅读的位置；只有用户已接近底部时才自动滚到底。
- AI 生成失败时保留用户输入，显示原因与重试；禁止清空对话。

## 8. 交互逻辑

### 8.1 先回答三个问题

任何页面都必须让用户快速知道：

1. 我现在在哪个阶段？
2. 这一屏要我做什么？
3. 做完后会发生什么？

### 8.2 主动作纪律

- 一个视图一个 Primary CTA。
- 次要动作降低饱和度和阴影，不与 Primary 并列争抢。
- 危险动作与主流程分离，并要求二次确认。

### 8.3 状态完整性

所有交互控件至少覆盖：

- default
- hover
- focus-visible
- selected / open
- disabled
- loading
- success / error（如适用）

### 8.4 表单与保存

- 行内校验优先；错误说明紧邻字段。
- 长表单支持自动保存和明确的保存状态。
- 切换页面、Phase 或布局时保留草稿。
- Rumination 改变热爱或优势后，如原“方向”失效，应显式提示重新确认，而非悄悄覆盖。

### 8.5 键盘与焦点

- 使用原生 `button`、`radio`、`checkbox`、`details`、`dialog` 和表单语义。
- Focus 使用 2px 当前阶段 `Deep` 描边 + 4px offset，确保在白底达到至少 3:1。
- 选择卡 radiogroup 支持方向键、Home、End。
- 弹窗锁定焦点，关闭后焦点返回触发器。

### 8.6 内容安全与数据权利

- OpenLife 帮助用户反思与决策，不将 AI 描述为心理治疗、医疗诊断或替用户作决定的主体。
- 关于我们、帮助、隐私与相关 AI 场景必须保留清晰边界说明，不用营销文案弱化它。
- 对话与报告属于用户；涉及数据的页面必须提供清楚的存储说明，以及可用的导出、删除和隐私入口。
- 未经真实产品配置支持，不虚构保存期限、服务响应时限、价格、权益或安全承诺。

## 9. 响应式规则

### 9.1 校验视口

每次交付至少检查：

- 1600 × 900
- 1366 × 768
- 1024 × 768
- 390 × 844
- 浏览器 200% 缩放
- 等效 320 CSS px 的 reflow 测试（通常为 1280px 视口下 400% 缩放）

### 9.2 断点行为

- 首页：≤1050px 五阶段卡转 3+2；≤720px 可变为横向 scroll-snap。
- 普通 Phase Chat：≤1030px 会话/辅助区进入抽屉；≤700px 以对话为唯一主列。
- Rumination：≥1250px 使用 47:53 与五优势单行；900–1249px 只有在左侧 ≥400px、对话 ≥620px 时保留双栏，否则选择区进抽屉，优势为 3+2；<900px 对话为主、选择区进抽屉；<700px 优势为 2+2+1。
- 个人空间：≤1050px 左导航改顶部；≤720px 卡片与表单单列。
- 购买弹窗：小屏改上下结构，比较表横向滚动或转条目式对比。

移动端不是桌面缩小版。优先保留当前任务、输入与主动作，将次要设置收进抽屉或 Popover。

## 10. 无障碍底线

- 正文与背景对比度达到 WCAG 2.2 AA：至少 4.5:1。
- 大字至少 3:1；控件边界与图标至少 3:1。
- 点击目标至少 44 × 44px。
- 不用颜色作为唯一状态线索。
- 所有图标按钮有可访问名称。
- 动态消息用合适的 live region，不重复朗读整个聊天记录。
- 200% 缩放以及等效 320 CSS px reflow 不遮挡、不横向溢出主要内容。
- Reduced motion 下所有核心功能与状态仍完整可见。

## 11. 明确禁止

- 五色平均铺满一个页面。
- Rumination 整屏紫色，或同时堆叠紫、绿、红三种强色。
- 整页大磨砂玻璃、玻璃套玻璃。
- 霓虹渐变、亮面高光、厚重阴影、过度 3D。
- 用 emoji 作为正式功能图标。
- 把装饰贴图放在正文或控件后面。
- 每轮聊天消息使用不同颜色。
- 让主按钮看起来像禁用按钮。
- 用很小的灰字承载关键说明。
- 在 Rumination 里重复添加普通阶段结论卡。
- 在阅读页面套用 Chat 的固定视口与隐藏滚动。

## 12. 开发实施建议

配套的 `openlife-tokens.css` 是 **OpenLife 应用级基础样式**：它会建立页面字体、背景、表单继承和 reduced-motion 基线。用于其他宿主应用中的单个组件时，应先用 CSS layer、Shadow DOM 或父级作用域隔离，不能无审查地全局引入。

默认浏览器基线为支持 `color-mix()` 与 `:has()` 的现代 evergreen 浏览器。若产品需要兼容更旧版本，应在构建阶段生成显式颜色 fallback，并用 JS 状态 class 替代 `:has()`；不能让选择、焦点或错误状态静默消失。

### 12.1 页面配置而非散落硬编码

建议为每个页面提供：

```js
const openLifeAppearance = {
  phase: "values",             // neutral | values | strengths | passion | purpose | rumination
  background: "flow",         // plain | tint | flow | illustration
  aiBubble: "dark",            // dark | light
  userBubble: "paper",         // paper | phase-soft
  conclusion: "mist",          // mist | paper | gradient | outline
  decoration: "lineBotanical", // none | lineBotanical | reportPreview
  motion: "system"             // system | paused
};
```

将这些字段分别映射为页面根节点的 `data-phase`、`data-background`、`data-ai-bubble`、`data-user-bubble`、`data-conclusion`、`data-decoration` 和 `data-motion`。组件只读取语义 token，不在内部复制五套颜色。旧原型已有本地存储字段时应写迁移适配层，不能直接清空用户已保存的外观和草稿。

配套 CSS 提供 `.is-loading`、`.is-success`、`.is-error`、`aria-busy` 和 `aria-invalid` 的视觉层。实现时仍需同步真实语义、状态文字与 `aria-describedby`；class 不能代替可访问状态。

### 12.2 推荐语义结构

```html
<body>
  <div class="ol-page" data-phase="values">
    <header>…</header>
    <main>
      <section aria-labelledby="page-title">…</section>
    </main>
    <footer>…</footer>
  </div>
</body>
```

### 12.3 设计验收顺序

1. 先检查内容与阅读顺序。
2. 再检查留白与布局比例。
3. 在灰度模式下检查层级。
4. 加入当前主题色并确认其语义。
5. 最后加入背景、植物、颗粒和动效。
6. 完成键盘、缩放、移动端、reduced motion 测试。

## 15. 成功标准

一个新的 OpenLife 页面不需要复制旧页面的每个像素，但必须让用户感到它属于同一个安静、可信的探索空间。

如果去掉五色和装饰，页面仍然清楚、舒服、有秩序；加回主题色后，用户能更快理解阶段与状态；加回动效后，页面只多了一点生命感，而没有多一层干扰——这就是合格的 OpenLife 设计。
