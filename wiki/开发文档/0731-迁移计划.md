⚠️ 005（历史 migration）不可逆，升级前**必须备份 app.db**。

### 1.2 激活码 schema 迁移（不进 alembic，独立脚本）

激活码存在 `data/simple/activations.json`（不在 SQL 库）。ADR-0008 新增 `code_type` / `vip_level` / `package_type` 等字段，存量码需补全为「完整码」。
**脚本**：`scripts/migrate_activation_schema.py`（自动备份、幂等、后端运行中拒绝执行）。
详见 `wiki/开发文档/0726-激活码schema迁移脚本说明.md`。

### 1.3 支付模块（P2a 支付宝，全新）

- 下单方式：**电脑网站支付 `alipay.trade.page.pay`**（返回收银台跳转 URL；0723 文档中的「当面付 precreate」已被 v2 替换，以代码为准）。
- 回调：`POST /api/v1/payment/notify/alipay`（**无登录鉴权**，靠 RSA2 验签；已被 `location ^~ /api/` 覆盖，nginx 无需单独放行，但维护模式会拦截——见 §3 Step 6）。
- 同步回跳：`ALIPAY_RETURN_URL` → 前端 `/payment/result`。
- 密钥：`src/backend/certs/alipay_app_private_key.pem` + `alipay_public_key.pem`（**不进 git**，需从旧服务器拷贝；.env 里路径为相对后端工作目录的 `certs/xxx.pem`）。
- 未配置密钥时：下单接口返回 503，不影响其他功能。
- 商品目录（ADR-0008，2026-07-28 调价后）：季度套餐 69 元 / 年度套餐 **128 元** / 延期统一 **20 元 +90 天** / 报告解读咨询 298 元。

### 1.4 报告 PDF v2（weasyprint，系统依赖最重的一块）

- 链路：markdown → HTML → WeasyPrint PDF，含品牌 logo 页眉/页脚、全页水印、末尾随机「落款签名」图（持久化在 `record.json` 的 `report_signature`）。
- 静态图（已进 git，无需搬）：`src/backend/app/static/assets/`（openlifelogo*.png、watermark_logo.png、signature_1~3.png）。
- **新服务器必须装系统库和中文字体**，否则 PDF 生成直接失败或全乱码（见 §3 Step 1）。

### 1.5 反馈截图 → 阿里云 OSS

`.env` 需带 OSS 配置（从旧服务器 .env 原样拷贝）：`OSS_ACCESS_KEY_ID / OSS_ACCESS_KEY_SECRET / OSS_ENDPOINT / OSS_BUCKET_NAME`。
⚠️ 若 OSS bucket 设了 IP 白名单，需加入**新服务器出口 IP**。

### 1.6 品牌更名（ADR-0012）

- 新域名 `openlife.beyondego.me`；旧 `xunlu.*` 双域名 nginx **301 永久跳转**。
- CORS 只保留新 origin；`FRONTEND_URL` / `ALIPAY_NOTIFY_URL` / `ALIPAY_RETURN_URL` 全部指向新域名。
- 支付宝开放平台需同步修改**授权回调域**（这是唯一触碰的第三方平台配置）。
- 站内公告按域名前缀判定 prod（`siteNotices.ts`），新旧域名不可并行长期共存。

### 1.7 其他新功能（无额外基础设施，知道即可）

- **Rumination v4**：矩阵组合模式（combo_session），全新前端 store + 路由。
- **试用码门控**：注册送试用码（values 阶段限 10 轮），写端点超限返回 HTTP 402。
- **账户注销**：30 天冷存（`ACCOUNT_DELETION_RETENTION_DAYS=30`），admin 可恢复。
- **报告解读咨询 / 团队分析**：年度套餐含团队分析模块。
- **LLM 模型配置后台**：admin 可在后台切换模型档位（009 表）。

### Step 5：配置 .env / .env.prod

从旧服务器拷贝的 `.env` 基础上，**逐项核对以下变量**：

```bash
# ── .env ──
# ① 域名相关（如还是旧域名值，必须改）
FRONTEND_URL=https://openlife.beyondego.me          # .env.prod 已覆盖，核对即可
ALIPAY_NOTIFY_URL=https://openlife.beyondego.me/api/v1/payment/notify/alipay
ALIPAY_RETURN_URL=https://openlife.beyondego.me/payment/result
# ② 密钥沿用旧值，不要重新生成：
SECRET_KEY=...                            # ⚠️ 改了 = 全部用户 JWT 失效
NEXT_SERVER_ACTIONS_ENCRYPTION_KEY=...    # ⚠️ 改了且前端 rebuild = Server Action 报错
# ③ OSS / SMTP / IMAP / DEEPSEEK_API_KEY：原样沿用

# ── .env.prod（维护模式，路径/容器名按新服务器实际改！）──
# 新服务器 1Panel 的容器名几乎必然不同（旧 prod 是 1Panel-openresty-UpQ6）
# 方案 A（推荐）：NGINX_RELOAD_CMD 留空/不写，maintenance.sh 自动探测 1Panel-openresty-*
# 方案 B：确认新容器名后显式配置：
MAINTENANCE_FLAG_PATH=/opt/1panel/www/sites/openlife/maintenance.flag      # 路径前缀以新服务器实际挂载为准
MAINTENANCE_PAGE_DIR=/opt/1panel/www/sites/openlife/maintenance
MAINTENANCE_TEMPLATE_PATH=/home/gitclone/BeingDoing/src/frontend/maintenance.html
NGINX_RELOAD_CMD="docker exec <新容器名> nginx -s reload"
BYPASS_COOKIE_NAME=bypass_maintenance
```

核对挂载路径的方法：`docker inspect <容器名> | grep -A2 '"Source"'`，确认宿主机 www 目录（可能是 `/opt/1panel/www`，也可能含 `apps/openresty/openresty` 中间层）。

### Step 6：1Panel 建站 + nginx 配置

1. **1Panel → 网站 → 新建网站**：域名 `openlife.beyondego.me`，申请 TLS 证书（Let's Encrypt）。
2. **反向代理**两条：
   - `/` → `http://127.0.0.1:3000`
   - `/api/` → `http://127.0.0.1:8000`，**用 `deploy/nginx-api-stream.conf` 的完整配置**（流式必须 `proxy_buffering off` + 300s 超时）。
3. **维护模式**：照 `wiki/开发文档/0705-nginx-prod.md` 的「文件 1/2/3」三段配置，把所有 `xunlu` 路径替换为 `openlife`：
   - 主配置加 `set $maintenance_on` 检测块（flag 路径 `/www/sites/openlife/maintenance.flag`）；
   - `/` 和 `/api/` 两个反代 conf（在 `proxy/*.conf` include 里！）第一行加 `if ($maintenance_on = 1) { return 503; }`。
   - ⚠️ 维护模式会同时拦截支付宝回调——**支付联调/上线期间如开维护，支付宝 notify 会 503**（支付宝会重试，但仍建议避开）。
4. 创建维护页目录：`mkdir -p <宿主机www路径>/sites/openlife/maintenance`。
5. **旧服务器 xunlu 站**：主配置改为 301 跳转（切流时执行）：

```nginx
server {
    listen 443 ssl;
    server_name xunlu.soulhappylab.com xunlu.beyondego.me;
    # ... 保留原 ssl_certificate 配置 ...
    return 301 https://openlife.beyondego.me$request_uri;
}
```

## 4. 关键坑位 TOP 8（踩过/高概率踩）

1. **certs / .env / app.db / data 都不在 git**——只 clone 代码等于什么都没迁。Step 0 的 tar 包是命根子。
2. **WeasyPrint 系统库 + 中文字体**——pip 装了 weasyprint 但没装 `libpango` / `fonts-noto-cjk`，PDF 直接崩或乱码。新服务器最容易漏。
3. **`NEXT_SERVER_ACTIONS_ENCRYPTION_KEY` 必须沿用旧值**——重新生成 + 前端 rebuild 后，用户端旧页面会报 "Failed to find Server Action"。
4. **1Panel 容器名和 www 挂载路径因版本而异**——不要照抄旧 prod 的 `UpQ6` / `/opt/1panel/www`；要么显式确认，要么 `NGINX_RELOAD_CMD` 留空让脚本自动探测。
5. **维护拦截 if 加在 `proxy/*.conf` include 文件里**，不是主配置——1Panel 反代的坑（详见 0705-nginx-prod.md）。
6. **支付宝验签用「支付宝公钥」**（平台下载），不是本地生成的应用公钥。
7. **支付宝授权回调域不改** → 支付回跳/回调全挂。这是本次更名唯一必须动的第三方平台配置。
8. **OSS bucket 若有 IP 白名单**，记得加新服务器出口 IP，否则反馈截图静默失败。
