# Wiki历史与实施记录

这里保存历次调查、设计稿、迁移说明和实施记录；文件名中的日期、“完成”“当前”和“唯一准绳”均指写作时的范围。当前开发从 [docs/DEVELOPMENT](../docs/DEVELOPMENT.md) 和 [docs/DECISIONS](../docs/DECISIONS.md) 开始，现行字段与业务分别见 [DATA_DICTIONARY](../docs/DATA_DICTIONARY.md) 和 [PRODUCT_RULES](../docs/PRODUCT_RULES.md)。

| 材料 | 用途与优先级 |
| --- | --- |
| [开发文档](开发文档/) | 按日期追踪需求、事故、实施与验收；同一文件多轮修订需读到末次决定，不能只摘第一版。 |
| [开发核心资料](开发核心资料/)、[历史记录](history.md) | 研究产品概念与早期结构；与更新决定冲突时只作为来源。 |
| [回归测试](回归测试/)、[debug](debug/)、[claude开发](claude开发/) | 解释某次验证或排障；测试通过是当时报告，不证明当前全量或生产通过。 |
| 顶层旧开发/部署/环境指南 | 保留原环境追溯；当前启动、路径、域名、密钥与数据库revision不得照搬。 |

已核实的重要替代链见 [HISTORY_EVIDENCE](../docs/HISTORY_EVIDENCE.md)，逐ADR状态见 [ADR索引](../docs/adr/README.md)，完整GitHub条目见 [ISSUE_HISTORY](../docs/ISSUE_HISTORY.md)。例如7月v4的chips/tool写卡已被ADR-0015替代，8月11轮出卡门槛被9月撤销，0919玻璃视觉又经多轮用户验收和ADR-0022修订；这些都不应恢复为“保护旧设计”的要求。

迁移手册只适用于其声明的起始版本和环境。备份、回滚、未知字段保留等需要继续核对，而旧主机命令不自动获执行授权。用户本轮已废止v3运行时，不表示要删除真实历史数据；明确保留的会员预留、设计母版和旧码兼容仍分别适用。一次性“不改某模块”通常是当次范围，不是永久架构禁令。

新的正式规则应写入docs当前规范或新ADR，并链接被替代的原文；历史完成记录尽量保持原貌，不改写过去的决定。
