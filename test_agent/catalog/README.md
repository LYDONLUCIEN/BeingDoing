# 固定测试用例目录

本目录是随开发交付的测试定义唯一入口。一个 JSON 文件对应一个稳定用例 ID，文件名必须与 ID 一致。执行器在 `test_agent/center`，实际后端测试在 `test/backend`；不要复制实现制造另一套业务规则。

每项分别维护：`title`、`module`、`purpose`（测试目的）、`inputs`（用户输入或操作）、`assertions`（独立合格标准）、`sources`（现行规范路径及规则）、`targets`（已实现的固定执行入口）、`timeout` 和 `core`。

`history-*.json` 是按现行产品规则核对的历史功能/修复回归，默认不新增核心。admin 可设为常驻、归档、编辑和一键运行；归档保留历史。目录中存在不等于本次通过，结果只属于实际运行的源码和用例修订。

## 每次开发必须完成

1. 从需求及现行产品规范明确前置条件、操作和独立断言；历史资料先检查是否被新决定替代。未实施计划、退役协议不作为当前运行规则。
2. 新增/修复行为时同步编写真实测试和本目录定义；复用同一 ID 更新修订，不为改标题重复建用例。允许路径、拒绝路径、会话/账户隔离按功能需要覆盖。
3. 在 `test_agent/changes/` 维护本次实际变动路径与用例关联。禁止把无关整棵目录关联到一个宽泛套件来消除覆盖缺口。
4. 运行对应入口及 `python -m test_agent.center.check_catalog`；区分失败、未运行、旧失败与新增回归。没有断言或能力未实现不能登记为通过。
5. dev 加载代码后自动登记；新 tag 归集开发增量。admin 已编辑的定义和核心/归档选择不能被新代码覆盖，差异以建议展示。

admin 草稿、修订和上下文在独立 `TEST_CENTER_ROOT/control.sqlite3` 维护，可导出。刷新业务快照不得覆盖这些资产；不让 Web 进程写 Git 工作区。需要随代码维护的 admin 修订，经开发核对后导出为本目录 JSON。

## 覆盖边界

- API 用例中的受控支付/模型/邮件响应不证明真实渠道通过。
- UI 用真实浏览器检查操作、跳转、禁用、遮挡与滚动；后端通过不能替代页面可用。
- AI 的目的和评价标准与被测提示词分开；独立单轮每项重置，连续多轮每个脚本重置，重复运行仍从同一起点开始。
- 尚未覆盖的规范保留在测试中心指南的缺口记录中，不能用目录数量宣称全部规则已覆盖。
