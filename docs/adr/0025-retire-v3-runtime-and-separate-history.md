# ADR-0025：退役沉淀 v3 运行链路，历史证据与现行契约分离

- 日期：2026-10-12
- 决定来源：维护者在本轮明确要求删除 v3 和旧 combo_id 设计，并核查历史决策；替代此前“保留 v3 后端”的过渡要求。
- 状态：接受并在 `clean` 实施；未部署，未迁移真实数据。
- 替代：ADR-0003 的运行模型、0707并行试验中的 v3 默认/A/B 分流、第一轮 clean 对 v3 的保留判断。

## 背景与取舍

前端已固定走 v4，后端仍有七步沉淀、两位矩阵索引、旧提示词、修复脚本和测试。把这套结构继续放在字段字典中，会使新开发误以为必须兼容新写入。只删字典无法阻止后台“跳到沉淀”继续写旧状态，或批量脚本把旧矩阵合成 v4 终选。

选择退役执行链路，保留可解释历史的只读能力。未选择按 `combo_id` 字符串全删：当前 v4 的 `combo_1` 是独立会话 ID，与旧“热爱索引＋优势索引”不同；盲删会破坏当前产品。也未选择自动迁移矩阵：一热爱×一优势的旧格子不等价于一热爱＋多优势会话，更不能推断用户终选。

## 实施边界

- 删除旧七步/矩阵/否定闸门/候选生成/A/B 服务、配置及专用接口；通用对话写接口拒绝 `phase=rumination`，要求走现行 v4 接口。
- 共用四阶段输入提取独立为 `rumination_inputs`；当前 v4 会话、判定与终选保持原契约。
- 后台跳转仅在沙箱初始化/读取 v4 状态并保留已有组合；前四阶段回退的沙箱快照清理下游新旧沉淀状态，原始报告不改。
- 历史 JSON 仅由 `legacy_rumination_export` 读取；不自动补矩阵、不产生 v4、不写回。现行导出携带原生 v4 快照，批量报告脚本只按原生终选判定完整性。
- `/version` 保持现有响应结构但固定 v4，不创建 A/B 分配。旧 ORM 与历史迁移保留用于识别存量表及账户删除。
- 专属测试随被移除功能退役；新增公开拒绝路径、原生 v4、输入提取和历史只读边界回归。旧测试失败数量减少不计为缺陷修复。

## 文档边界和后果

现行字段字典仅定义当前 v4 的 ID；旧字段仅出现在明确标为历史的解释、读取器和历史测试输入中。历史 ADR/issue 保留为什么改变的证据，不再授权恢复旧流程。接口移除对旧客户端是明确不兼容变化，见 [API 契约](../API_DOCUMENTATION.md)。

本次不修改用户历史数据、不回填终选、不合并账户。已有 Markdown 报告仍走原授权/审核读取与渲染；缺失原生 v4 终选的旧探索，不伪造为可生成的新报告。若需迁移未完成旧探索，应单独决定数据映射并在一致快照上演练。

验证与限制见 [TESTING](../TESTING.md)；替代链和约束分类见 [DECISIONS](../DECISIONS.md) 与 [HISTORY_EVIDENCE](../HISTORY_EVIDENCE.md)。
