# ADR-0007: 会员体系按真实代扣设计，本期只交付表与接口、不对外开放

**状态**: accepted
**日期**: 2026-07-19
**决策者**: 产品 + 开发 Grill

## 背景

「连续包月」有两种实现：到期提醒用户手动扫码续费（无门槛），或真实自动扣款（微信委托代扣 / 支付宝周期扣款，需单独签约、小商户常批不下来）。

## 决策

按**真实代扣**写代码：首月支付时签约、之后每月自动扣款、「取消」= 解约、当月权益用到期末。但商户号的代扣权限尚未申请下来，因此本期会员体系**只交付数据库表（subscriptions）与用户会员字段、以及购买/取消接口**，用 feature flag（`MEMBERSHIP_ENABLED`）整体关闭，线上 v1 仅售卖激活码。

## 后果

- 代码库中存在「已写好但不可达」的代扣链路（签约、扣款计划、解约回调）——这是刻意的，不要当死代码删除。
- 代扣链路在商户号审批通过前无法端到端测试，验收以接口级测试 + 沙箱模拟为准。
- 数据模型预留 `agreement_no`（签约号）、`auto_renew` 字段，避免上线时迁移。
