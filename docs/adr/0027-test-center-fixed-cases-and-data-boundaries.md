# ADR-0027：测试中心固定用例与测试数据边界

- 日期：2026-10-13
- 更新：2026-10-14（所有者确认至 Q15）
- 状态：接受、部分实施；Q1–Q15 与后续追加要求已确认，三个阶段首版及历史回归库已本地实现；具体限制见 TEST_CENTER，未部署。
- 决定来源：所有者在 `grill-with-docs` Q1–Q15 的回答及补充。
- 讨论与代码证据：[手机适配与测试中心](../MOBILE_AND_TEST_CENTER.md)。
- 实施方案：[三阶段交付与验收](../MOBILE_AND_TEST_CENTER_PLAN.md)。

## 背景与选择

项目已有后端测试、管理员保存点、批量场景运行与 Prompt Lab，但三类测试尚未统一，部分执行器或文本检查可能产生假通过。测试中心需要支持 admin 用自然语言定义业务/API、UI 交互和 AI 对话效果用例，并使发布回归可重复、结果可追溯。

已接受的边界：

1. 自然语言用于辅助编写；生成可读步骤与预期，试跑确认后保存固定版本，后续执行该版本。**用户输入与断言标准分别定义和保存**，不能用显示了输入文本来证明 AI 回答正确。
2. 区分核心测试与版本测试。**每次功能/修复交付时同步生成或更新用例定义、断言和变更清单，随代码保存，dev 加载该提交后自动登记为待测**；同一用例形成修订，不重复新建。未打新 tag 时暂挂最近 tag 的开发增量。tag 是提测起点，不代表已经通过或已上线；新 tag 归集其实际包含改动的用例、固定该次提测清单，相对同一发布线上一正式 tag 组织增量验收，验证后发布相同构建。未包含的提交不混入，旧 tag 指向和原验收历史不覆盖。
3. 功能/发布回归只测实际使用的一套提示词。不同提示词比较可通过 Prompt Lab 配合多个测试用例开展，不要求每次上线功能测试运行多提示词矩阵。
4. 生产数据以一致脱敏快照单向进入测试；隔离支付、邮件、对象存储等外部操作。测试定义、保存的对话上下文与运行记录独立保留，不随业务副本刷新而被覆盖。
5. **每个独立用例具有干净起点，同一用例内的连续步骤共享状态**。局部 API 用例使用临时数据库及必要文件，流程用例使用独立账号/数据/浏览器状态，AI 回放从保存的上下文派生副本，历史兼容/迁移/全局统计使用完整脱敏快照；完成后丢弃执行副本。直接调用接口只针对隔离测试环境。
6. admin 勾选常驻表示加入核心测试；普通版本用例默认随该版本运行，后续再次涉及相应功能时重新纳入。删除从后续列表移除/归档，保留原版本用例与运行结果；人工修改的输入/断言不能被增量生成覆盖，只生成待核对的修改建议。
7. AI 硬规则或必达关注点不满足记失败；语义无法判断记待复核，必测项待复核不能显示为全部通过。保留首次运行结果；人工复核独立记录，不能覆盖原自动判定。每批固定各场景实际生效的提示词与模型配置，配置变化从下一批生效。
8. 第一版测试中心部署在 **dev 服务器的 admin**；使用专属执行进程和隔离数据，不在生产服务进程执行破坏性测试。
9. 真实 AI 测试默认每用例 1 次，admin 可选择重复次数；每次恢复相同起点并保留全部结果。运行前展示模型、用例/重复数量及可估算费用，支持批次预算上限与停止。普通业务/UI 逻辑测试可用固定模型响应，必须与真实模型效果测试分别标识和统计。
10. 交付顺序已确定：第一阶段测试底座与手机首页；第二阶段完整手机主流程并随改动补测试；第三阶段完善自然语言用例编辑和 AI/v4 回放。Prompt Lab 跨提示词实验仍为独立后续范围，微信支付本期不做。

## 取舍与影响

固定用例需要在编写时明确验收标准，但能避免每轮临时生成动作造成结果不可比。单套实际提示词使发布回归范围清晰，Prompt Lab 另承担试验；隔离运行数据增加环境准备成本，但使数据刷新不会损坏长期测试资产。

自动生成需要开发变更、业务验收与已有用例共同作为依据；本决定不承诺仅从代码差异即可穷尽正确业务规则。测试覆盖范围、未生成/未执行/模拟执行及既有失败应如实可见。未打新 tag 的开发增量应与原 tag 的历史验收区分，实际执行记录具体提交与用例修订，不能借版本分组覆盖旧验收结论。

阶段一新增固定用例登记、增量清单与隔离执行；原沙箱/Prompt Lab 入口保留。后续已接入当前 v4 组合起点、单轮/连续聊天历史回放及显式预算；2026-10-14 追加 AI 业务回放，通过既有 API 在每轮新进程/数据副本推进结论、摘要、判定、终选及报告 Markdown，不增加业务绕过入口。真实模型尚未验收，生产脱敏基准导入仍未完成。不覆盖现行真实数据保护约束，也不授权生产操作。

## 实施确认与验证

Q1–Q15 的产品决定已记录；[实施方案](../MOBILE_AND_TEST_CENTER_PLAN.md) 汇总首批覆盖、页面行为、自动登记和快照准备方式，工程默认值已由 Q15 接受。文档确认不等于已经测试或部署；真实服务器路径、资源和渠道配置在对应实施阶段核对。

实施时需验证真实动作与拒绝路径、失败能够被正确发现、各独立用例互不污染、版本及结果可追溯、数据刷新不覆盖测试资产，且测试无法通过外部渠道影响生产。

三个阶段的本地落地与边界见 [测试中心指南](../TEST_CENTER.md)，验证见 [TESTING](../TESTING.md)；已接入目录约束的用例编辑、固定 AI 单轮/连续对话回放、预算和人工复核；真实模型效果、dev 部署与生产脱敏数据导入仍未验收，不能从离线框架测试推导全部能力已完成。

后续确认：历史规则用例统一维护在 `test_agent/catalog/`，分别记录目的、输入、断言及现行来源。每次开发由开发者/代理同步新增或更新定义/脚本/变更关联，admin 可一键运行、改为核心、归档或人工修订。保留 60 个已核对的细分历史用例，不将退役规则或缺口清单笼统标为覆盖。普通 PC 布局优先，以实际可用宽度决定辅助面板收起，高度不足使用内部滚动，不切换 guided/classic 工作方式。
