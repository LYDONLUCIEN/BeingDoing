# ADR-0014: 套餐交付改为全量未绑定码 + 消耗升级，年度套餐调价 ¥159

**状态**: accepted
**日期**: 2026-08-05
**决策者**: 产品 + 开发 Grill
**取代**: ADR-0008 中的交付模型部分（「季度套餐 = 自动升级试用码/发新码自动绑定；年度套餐 = 1 自用码自动绑定 + 2 赠品码」）

## 背景

ADR-0008 的交付模型是「支付成功即自动升级试用码（无试用码则发新码并自动绑定购买者）」。产品判断该模型有两个问题：

1. **剥夺了用户对码的处置权**：用户可能购买年度套餐是为了送朋友，但自用码已被强制绑定/升级，无法 3 个全送。
2. **自动升级不可逆**：试用码被静默升级为完整码，用户没有知情与选择的机会；一旦用户对交付预期不符，只能退款。

同时年度套餐定价从 ¥128（2026-07-28 由 ¥99 调整）再调整为 **¥159**（3 个码对应 3 人使用的「三人价」）。

## 决策

- **交付模型**：套餐订单一律交付**未绑定**完整码（季度 1 个、年度 3 个），不再自动升级试用码、不再自动绑定购买者。所有码「发码自取」，可自用可转赠；取消自用码/赠品码的区分。
- **消耗升级（Consume-to-Upgrade）**：试用码升级的唯一路径改为用户主动发起——用户手持一个未绑定未使用的完整码（自购或被赠均可），选择消耗：该码标记作废（新状态 `consumed`，meta 记录 `consumed_into` 与来源订单，不可再用不可退），已开聊的试用码走现有 `upgrade_to_full` 原地升级（码字符串、对话记录、session 全部保留）。用被赠的码升级时，试用码所属人记为原购买者（保持 ADR-0010 双角色与报告授权链路）。
- **触发入口**：
  - 支付结果页弹窗：检测到有**已开聊**（≥1 条用户消息）的试用码时，年度 3 选 1 / 季度确认 1；带「不再提醒」勾选（存后端用户设置，跨设备生效）。
  - 两种试用拦截点（10 轮上限 `trial_limit_reached` + values 推进被拦 `trial_phase_locked`）挂双选项：① 直购升级（季度/年度可选，属用户主动发起，支付成功后自动消耗升级，不再二次弹窗）；② 使用手头已有未绑定码升级。
  - 「我的激活码」页提供「升级我的试用码」入口。
- **退款口径**：一单多码时，任一码被激活（claim）或消耗（consumed）→ 整单不可退。
- **价格**：`ANNUAL_PRICE` 12800 → **15900**（分）；季度套餐 6900 不变。
- **码模型**：维持码串模式（曾讨论「激活名额池/账户间 +1/-1 账本」，已否决：C 端送朋友场景码串是最简载体，收礼人本就必须注册登录才能激活，名额账本只增复杂度）；只需保证码不重复。

## 后果

- `PaymentService._deliver_package` 简化：不再查试用码、不再 `upgrade_to_full`、不再 `claim_owner`；统一发 N 个未绑定码（年度仍写 `purchaser_user_id`/`source_order_id` 以维持所属人视角与团队分析）。
- 订单 meta 语义变化：`upgraded` 废弃；直购升级订单以 meta 标记 `intent=upgrade_trial`，交付后发码并自动走消耗升级（同一代码路径，审计完整）。
- `ActivationStatus` 新增 `consumed`；admin 码列表、退款校验需识别该状态。
- 新增接口：`POST /simple-auth/codes/apply-to-trial`（消耗升级）。
- 前端新增：支付结果页升级弹窗组件、试用拦截弹窗双选项、「我的激活码」页升级入口与未绑定码展示。
- 用户设置新增「升级弹窗不再提醒」开关字段。
- 存量已交付订单与已绑定码不受影响，无需数据迁移。
- 交付邮件与商品目录文案需同步（不再有「自用码已自动绑定」表述）。
