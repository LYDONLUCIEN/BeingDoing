# ADR-0028：v3 已定稿老报告严格收口到报告页

- 日期：2026-10-20
- 决定来源：所有者确认老实验用户无需查看 v3 页面或过程数据，但不应进入看似可用、实际被锁定的 v4 新建流程。
- 状态：接受并在本地实现；未部署，不改真实历史数据。

## 背景

v3 运行链路已由 [ADR-0025](0025-retire-v3-runtime-and-separate-history.md) 退役，前端只运行 v4。部分老报告在 v3 时代已经定稿并生成 Markdown；其 `record.json` 保留旧 rumination 会话与锁定状态，因此报告仍可读。用户进入当前第五轮时会看到空 v4 工作台，但旧锁定又会拒绝所有 v4 写操作，形成“引导新建却禁止创建”的矛盾。

## 决定

增加派生标记 `legacy_report_ready`，仅在以下证据同时存在时为真：

1. 前四阶段均有已选定会话；
2. rumination 有旧 `selected_session_id` 且已锁定，排除 `admin_mock`；
3. 原生 `rumination_progress.json` 存在且 schema 为 1–3；
4. v4 没有任何实质数据：无 combo、无 active 组合、未选择/提交终选，且仍停留在 matrix；
5. `report_markdown.md` 与生成时间均存在。

普通用户进入 `/explore/chat/rumination` 前读取该标记；为真则直接进入报告页。标记由后端按当前文件派生，不持久化、不回填 `final_selection`、不迁移 v3 数据。任一条件不满足、读取失败或 API 请求失败时都保守进入 v4 原流程；任何 v4 数据存在时不得收口。管理员调试入口不受该重定向影响。

## 边界

- 不恢复 v3 页面，不向普通用户展示 v3 矩阵或过程数据。
- 不生成新报告，不强制重生成旧 Markdown；报告页仍执行原有归属与审核门控。
- 这不是未完成旧探索的数据迁移。未完成或无可靠报告缓存的旧数据不识别为 `legacy_report_ready`。
- 旧报告需要重新生成时，必须另行确认 v3 内容口径；不能用当前 v4-only 生成器静默覆盖。

## 验证

新增后端正反向用例：v3 证据齐全才为真，任何 combo、终选草稿/提交、active 组合、离开 matrix、缺旧进度或缺 Markdown 均为假。浏览器固定用例验证老报告直达报告页且正常 v4 首开不受影响；本地数据只读扫描确认含实质 v4 数据的报告均不命中。
