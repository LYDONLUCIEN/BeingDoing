# ADR-0005: 支付走官方双线接口（微信+支付宝），而非静态收款码人工确认

**状态**: accepted
**日期**: 2026-07-19
**决策者**: 产品 + 开发 Grill

## 背景

支付模块需要选择确认方式：静态个人收款码 + admin 人工确认（零门槛、当天上线），还是官方支付接口 + 服务器回调自动确认（需商户号与资质，开发量大）。

## 决策

选择官方接口，且 **微信 Native 扫码与支付宝同时接入**（不是先单渠道）。支付回调端点（`/payment/notify/*`）不做登录鉴权、改用渠道签名验证；订单状态机以回调为唯一支付成功来源。退款同样接官方退款 API（两个渠道），不做纯线下退款。

## 后果

- 需要两套商户号、两套密钥证书、两套回调验签逻辑，开发量接近翻倍——已被接受。
- 回调 URL 需公网可达（HTTPS），部署侧 nginx 需放行 `/api/v1/payment/notify/*`。
- 订单模型以 `channel` / `channel_transaction_id` 预留双渠道；超时未支付订单由 APScheduler 周期关单。
- 退款限定「仅未使用激活码可退」，已使用的码拒绝退款走线下协商（见 CONTEXT.md「退款规则」）。
