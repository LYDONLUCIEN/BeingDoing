# 架构与开发决策

核对日期：2026-10-12。当前分支 `clean`，发布基线 `v1.8.0`。本文件说明**现在采用什么、为什么、什么条件下可以改变**。历史过程见 [证据研究](HISTORY_EVIDENCE.md)，全部 GitHub 条目见 [历史索引](ISSUE_HISTORY.md)，本次代码变更见 [开发变更记录](CHANGELOG.md)。线上配置及迁移状态未核验。

## 文档如何生效

1. 当前业务契约读 [产品规则](PRODUCT_RULES.md)、[字段字典](DATA_DICTIONARY.md)、[API](API_DOCUMENTATION.md)；工程工作读 [贡献规范](../CONTRIBUTING.md)。
2. 本文件和 [ADR 状态索引](adr/README.md)解释约束来源及替代关系。最新明确的产品决定可以替代旧决定；代码用于核对是否落实，不能用代码现状悄悄撤销尚未实施的决定。
3. `docs/历史文档/`、`wiki/开发文档/`、`tasks/` 和旧 issue 是证据或提案。日期较新、issue 已关闭、清单已勾选，都不能单独证明部署完成。未执行的计划不自动成为当前待办。
4. 出现冲突时登记“当前实现／历史决定／缺失证据”，不任选一句“必须”“不可改”作为永久规则；也不把过去改写成从来如此。

约束有四类：**现行不变量**（保持安全和数据含义，改变需新决定与迁移验证）、**存量兼容**（在相关历史记录仍存在时生效）、**阶段条件**（满足退出条件可调整）、**未落地决定/提案**（不能当已上线功能）。没有不可讨论的架构；禁止的是未经决策、迁移和验证改变契约。

## 现行选择与原因

| 主题 | 过去及变更原因 | 当前选择 | 约束类别与改变条件 | 证据 |
| --- | --- | --- | --- | --- |
| 身份和产品 | 激活码、会员和付费标签曾容易混作账户权益；新产品还会有订阅和一次性商品 | 共用 `users.id`；订单、探索、订阅、权益独立；按激活码索引报告仍验证归属/授权 | 现行不变量；新增产品明确权益来源与期限，不能另建平行账户或把 lifetime 改成 annual | ADR-0010、0024；研究 §4/7 |
| 前四阶段 | 旧11轮门槛妨碍自然出卡；点击即出卡绕过咨询判断 | 自然出卡无最小轮数；常驻手动入口满足界面条件后先 judge，再生成或继续引导；保留 STATE_JSON 与 pending 状态 | 现行契约；变更需验证确认、拒绝、继续聊、重访和试用计数 | #87 → `1a98a71` → `a513961`；研究 §3 |

| 延期 | 旧按档位/套餐分价难解释 | 首次过期可主动领一次7天；付费9.9元/7天，不可退 | 现行契约；旧订单价格仍按原值解释。它是探索码延期，不是订阅续费 | #67 → ADR-0016 |
| 支付与退款 | 浏览器返回或人工静态收款不能作到账凭证；整单退无法处理部分未用商品 | 验签通知＋服务端查单/补偿；支付和交付分开；行级分摊、退款申请/审批/执行、成功后累计 | 现行不变量；渠道幂等、审批重验、金额整数分和不可超额保留；新商品另定核销规则 | ADR-0005、10-05退款定稿、#102；研究 §8 |
| 券 | 单个 coupon 槽不能表达多次使用和并发占用 | `coupon_redemptions` 每订单记录；条件更新守卫容量；部分退不返券，符合规则全退返还 | 现行契约＋存量兼容；旧裸码精确匹配有明确长期兼容决定，不能为格式统一直接删掉 | 10-06多次券定稿、#101 |
| 报告审核 | 只在访问报告页触发会漏生成；随机时限难预测 | 终选提交启动审核/预生成，页面查询兜底；固定24h，历史 pending 保持原deadline | 现行契约＋存量兼容；扫描间隔不是秒级交付承诺；自动/人工对外文案是另一个产品问题 | ADR-0009 → #83 → #91；研究 §9 |
| 报告复核 | 用户重复生成可能覆盖已交付内容、重复消耗模型 | 用户提交复核；staging 新稿经管理员发布后替换并备份；运维 force 授权保留 | 现行不变量；重新渲染 PDF 不触发重新生成 Markdown；不可用旧接口绕过复核或归属 | #80、#89；研究 §9 |

## 未落地差异和后续决定

2026-10-13，所有者暂停新产品形态讨论，转回 BeingDoing 后续功能开发。下列跨产品讨论保留原有决定状态和历史依据，但未实现规则不成为当前功能要求或自动待办；恢复时重新确认范围。

- **年度价格**：#67 与 `b123969` 已把99改128；更晚 ADR-0014 写159，未找到实现或撤销。当前代码默认 `ANNUAL_PRICE=12800`，线上覆盖未知。产品需核对部署配置并明确是否实施159；清理不改价、不重算历史订单。
- **订阅和购物车**：共享账户已确认；月/年周期、自动续费还是手动续费、商品目录、权益期限、券适用范围、混合结算、退款与历史报告入口尚需设计。ADR-0024 不代表这些功能已实现。
- **个人主页与简历**：已接受一账户维护一份履历主页、修改自动更新、按内容选择与侧重点导出多版本简历；当前重要里程碑包括完成平台报告测评、达成平台输出的职业成长路径关键节点，认定方式与发放时点待定。用户可完全隐藏自己，此时只能看他人的公开摘要。**暂定采用**：通过平台求职／招聘时展示全部里程碑，其他场景可隐藏；这替代此前所有导出与合作场景均必显的口径。保留记录与对外展示分别定义。规则、复查点及替代原因统一维护在 [跨产品边界](PRODUCT_EVOLUTION.md)。新产品尚未实现，认证标准、摘要字段、访问角色、更正撤销及留存期限待定。
- **平台认证与推荐**：已接受必须经平台认定，个人自行标记完成不直接获得认证。“可靠性”已明确主要指经历与资料真实；另希望从报告出发理解招聘／合作中的能力和性格匹配。具体维度、证据、认定方及有效范围尚未定义，不能从现有报告结论或 `balance_found` 推导真实性或能力认证。详见 [CERT-01 与待对齐概念](PRODUCT_EVOLUTION.md)；[四力画像、量化及资料收集建议](PROFILE_MODEL_PROPOSAL.md) 为未接受提案，尚未实现。
- **存储迁移**：#59关闭原因是暂缓；有v1.8.0标签不等于完成迁移验收。全量入库、PG、移除补偿均未授权为本次顺带变更。
- **上线状态**：未核实服务器迁移023/024/025、支付渠道、真实存量数据或部署覆盖值。先在一致且脱敏的 DB＋data 副本演练，再作发布结论。

## 后续开发如何记录决定

新增 ADR 写清：问题和触发条件、旧方案为什么不足、选择和备选、字段/接口含义、兼容和数据迁移、约束适用范围与退出条件、验证及尚未核实部分。状态使用“提案／接受未实施／已实施／部分替代／退役”。替代时链接新旧双方，保留原决定正文；完成实现后在变更记录关联提交与测试，不用 issue 关闭状态代替验收。
