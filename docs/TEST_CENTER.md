- 分开筛选核心/当前版本和 API/UI/AI，用例输入/操作与断言独立维护；源码目录自动导入，人工修订与草稿另存控制库。

API 套件包括认证、订单/交付、退款、优惠券、激活码/试用、注销/恢复、聊天完成/归档和测试中心自身。浏览器套件包括首页/导航、admin 操作、前四阶段聊天的手机抽屉/输入法/流式禁用/会话归属、沉淀组合/草稿/终选、注册/个人空间/报告/现有支付界面、目标回复判定真实性。

## dev 启动

先按 [操作手册](OPERATIONS.md) 核对 dev 的目录、进程账号与资源。本次没有修改服务器或真实 `.env`。以下环境变量通过 dev 服务管理器配置，不用于生产：

```sh
# 在仓库根目录；替换为 dev 上专属控制目录的绝对路径。
export APP_ENV=development
export TEST_CENTER_ENABLED=1
export TEST_CENTER_ROOT=/absolute/dev/test-center-control
export PYTHONPATH=src/backend:.
```

后端进程需要同样的 `TEST_CENTER_ENABLED`、`TEST_CENTER_ROOT`；控制目录必须在业务 `data/` 和源码快照范围（`src/frontend`、`src/backend/app`、`test_agent` 等）之外，建议放在仓库之外，避免运行副本递归复制与业务数据覆盖。worker 使用单独进程，首版支持 Linux/macOS，依赖 POSIX 进程组及文件锁：

```sh
python -m test_agent.center.worker --control "$TEST_CENTER_ROOT"
# 运维/验证时可使用 --once：领取并执行一个批次后退出。
```

依赖沿用后端锁文件与现有 pytest/pytest-asyncio/anyio。前端及浏览器分别在其目录按锁文件安装：

```sh
cd src/frontend
npm ci
```

```sh
cd test_agent/l2
npm ci
npx playwright install chromium webkit
```

Linux 若缺浏览器系统库，按对应系统安装 Playwright 所需依赖。`PLAYWRIGHT_BROWSERS_PATH` 可显式指定安装目录。worker 不自动联网安装依赖，缺依赖显示环境错误。运行 UI 时会在临时目录启动 Next dev，仅绑定本机随机端口，使用当前前端源码和已安装依赖；截图、trace、JSON 报告放在控制目录。

执行副本不继承服务端密钥，不复制 `.env`、真实 DB、业务 data、证书、日志或保存点运行注册表。普通 API 通过网络守卫拒绝真实外部调用；浏览器所有 API 使用受控响应，外部网页请求拒绝。**这是受信任仓库测试的进程/数据隔离，不是任意代码的操作系统沙箱。** dev worker 应使用无生产访问权限的专属账号；安装好的依赖在批次期间保持不变。

## 开发登记和 tag

1. 在 `test_agent/catalog/<id>.json` 提交固定定义：`id/title/module/kind/core/purpose/inputs/assertions/sources/targets/timeout`。文件名必须匹配 ID，API 仅允许 `test/backend/test_*.py` 及其固定节点；UI 允许实现过的套件及已编译的明确步骤，不接受 shell。来源写明现行规范路径与对应规则。
2. 在 `test_agent/changes/*.json` 提交 `id/summary/paths/cases` 关联。每次功能/修复由开发者或开发代理生成并审阅实际测试脚本，不能仅补一句描述冒充可执行测试。
3. dev 读取新代码后的目录请求自动幂等登记。已有修订及管理员常驻/归档配置保留；输入或断言变化形成新修订。
4. 未打 tag 显示“最近 tag · 开发中”；新 tag 只归集其祖先范围内的增量。缺用例关联的业务文件、未知用例、脏源码或未打 tag 均阻止发布验收。
5. 发布验收必须运行完整核心+当前版本集合，不能靠取消勾选获得通过。每次验收固定自己的清单，后续常驻/归档、代码或定义变化需要新验收记录。

```sh
PYTHONPATH=src/backend:. python -m test_agent.center.check_catalog
```

此命令在临时控制库验证登记和覆盖缺口，不改业务数据。当前 `v1.8.0` 以来尚有历史改动未补登记，会如实列出并阻止发布验收；本次只登记已验证的范围，未把全部历史改动笼统关联为已覆盖。

开发者全量后端验证必须使用独立副本入口；旧测试未全部自带数据库隔离，不能直接从共享工作区运行全量 pytest：

```sh
PYTHONPATH=src/backend:. .venv/bin/python -m test_agent.center.verify_backend --output output/backend-本次唯一名称
```

可在命令末尾添加固定 pytest 文件/节点。输出目录必须是新的；该入口不复制业务数据、`.env` 或密钥，使用临时源码/数据库和网络守卫，保留 JUnit、日志和源码摘要。

重跑创建新批次，使用**当前检出的源码和当前用例修订**，旧结果及摘要保留。历史证据不能自动继承到新代码。首版不会自动切 Git 分支或替换服务器构建；上线仍需按操作手册部署已验收的同一候选构建，并补充生产配置、渠道及现场验证。

## 存储、保留与排障

`TEST_CENTER_ROOT/control.sqlite3` 是独立控制库（自身 schema v2；从 v1 幂等增加草稿、上下文、调用与复核表，不替换旧数据），保存定义修订、管理员集合调整与批次结果；不使用业务 Alembic 库。`runs/<id>/` 保存清单对应的源码摘要和证据。临时 `source/`、`work/` 正常结束后移除，结果/定义不自动删除。空闲低于 512 MiB 时停止接收新任务，页面展示占用和剩余容量。

首版没有 UI 物理删除证据功能。运维备份/整理时先停 worker，保留控制 DB 及其引用的证据；归档用例不删除旧证据。生产快照与测试资产分开管理，不能以刷新业务副本为由覆盖控制目录。

- 排队不动：检查页面执行器在线状态、worker 的控制目录是否与后端相同、进程日志及依赖。
- 环境错误：下载 `execution.log`、`results.xml` 或浏览器报告；不存在/不支持/未执行不视为通过。
- 浏览器失败：截图与 trace 均保留；可使用 Playwright Trace Viewer 检查执行过程。
- 旧保存点没有明确用户输入时，不能把“期待答案”当作输入。旧 L3 占位动作现在失败，L4 无目标断言进入待复核，replay CLI 仅完成回放返回非通过状态。这是纠正旧判定口径。


## 管理员编写与修订

点击「编写新用例」，分别维护测试目的、前置状态、用户输入/步骤、断言和运行设置。API 使用已登记完整模板；UI 可从首页、聊天、沉淀、个人空间的受控场景编写新的步骤组合。编译器是确定性的允许目录，不付费调用模型，也不把自由文字或生成代码交给 shell。未知动作/标准保存为待澄清草稿，不能保存成可执行用例；任意业务操作的自动编程尚未实现。

UI 每行一个步骤，例如 `打开注册页面`、`填写：邮箱 = case@example.invalid`、`点击：发送验证码`；聊天可写 `输入消息：内容`，键盘支持 `按键：Enter` / `Escape` / `Tab`。断言支持 `应显示：文字`、`不应显示：文字`、`按钮禁用：名称`、`按钮可用：名称`、`应跳转：/about`、`输入应为：内容`、`页面无横向溢出`。加 `第2步：` 指定检查时机，否则检查最后一步。用例执行于隔离前端，两浏览器分别使用手机/桌面视口；布局不同的操作需明确在两种布局中都可执行，不能静默跳过找不到的控件。

AI 输入每行一项，断言每行一项。历史回放可选独立单轮或连续多轮；业务回放的步骤语法见下节：

- `回复非空`：本轮可见正文非空。
- `回复包含：…` / `回复不包含：…`：只检查本轮可见正文，隐藏 STATE_JSON、用户输入与历史不能帮助命中。
- `语义：…`：明确必达点与禁止行为，额外请求一次判定模型；返回依据不完整或有歧义则 `needs_review`。
- `第2轮：回复包含：…` 等前缀只检查指定轮次；无前缀则每轮都检查。每轮必须有标准。语义判定同时获得测试目的和对应历史，但不能用历史文字冒充本轮回复证据。

生成草稿后检查固定定义，再「确认并保存用例」。每次保存生成内容摘要修订；排队任务继续使用原修订。并发编辑须基于最新修订，旧编辑器不能覆盖新修改。源目录的新定义不会覆盖管理员改过的定义；页面展示源码候选供核对。核心/归档调整与历史仍保留。可导出该用例的定义修订和引用上下文 JSON；草稿可重新打开修改。

自建用例通过勾选诊断或设为常驻运行；代码发布增量仍依赖开发清单登记，手写描述不会自动替代码覆盖缺口背书。

## AI 起点与当前提示词

支持手工录入脱敏背景与历史，或按调试激活码读取**当前**前四阶段线程 / v4 指定组合的预览。预览不保存、不恢复或推进原业务；确认脱敏后保存到控制库。v4 只带选定 combo 的消息、摘要、用户原文结论卡，以及前四阶段背景与价值观，不混入另一组合。前四阶段固定题库，避免每次随机抽题。当前预览只接收可继续对话、未锁定且未分析中的起点；业务回放可从该起点推进确认/判定/锁定。手填结构化线程状态仅是明确声明的测试前置条件。

读取的是当前调试工作区起点；不是任意历史时刻的全业务数据库恢复。若要退到旧轮次，需要在编辑器同时核对历史、摘要、进度和卡片，不能仅截断消息却保留未来状态。自由文本脱敏需要人工检查，不宣称正则足以消除所有隐私信息。

独立单轮每条输入恢复保存点；连续多轮在同一脚本中承接前轮输入和可见回复，每次整组重复仍恢复同一起点。原上下文不修改，用例之间不共享结果。前四阶段使用实际运行路由的 `_build_system_prompt` 与历史裁剪；v4 使用 `build_chat_messages`。执行来自本批固定源码，记录实际发送消息、提示词摘要、上下文摘要、模型参数及执行器版本。提示词来自候选构建的现行模板；不加载 Prompt Lab 的调试覆盖，也不更改其 global current。模型配置是测试中心显式配置；部署时核对它与线上对应场景一致，不能把未核对的环境自动视为生产等价。

**独立/连续模式只回放聊天历史；业务回放模式执行既有产品流程。** 两种模式的结果分别解释，不能将历史回放说成完整业务验收。AI 回复自动判定、每次结果和人工复核并列展示；人工复核不改自动状态或整批发布结论。

## 业务回放（2026-10-14，本地实现，未部署）

管理员在「对话方式」选择「业务回放」。输入与标准分别保存，未知步骤留作待澄清。只接受已有产品动作，不能填写 URL、执行路径、代码或“跳过权限检查”等指令。

| 阶段 | 输入步骤 | 常用标准（必须带 `第N步：`） |
| --- | --- | --- |
| 前四维 | `发送消息：内容`、`请求结论`、`确认结论`、`再聊聊` | `结论状态：none/pending/confirmed/rejected`、`线程完成：是/否`、`结论包含：文字`、`摘要包含：文字` |
| 沉淀 v4 | `发送消息：内容`、`填写结论：用户原文`、`确认结论`、`再聊聊`、`跳过组合`、`选入终选`、`提交终选` | `组合状态：discussing/concluded/abandoned`、`判定状态：none/analyzing/done/failed`、`终选提交：是/否`、`报告包含：文字` |
| 通用 | 同上 | `接口状态：400`、`阶段锁定：是/否`、`回复非空`、`回复包含：文字`、`回复不包含：文字`、`语义：具体要求` |

表格中的斜线表示可选值，不是整串输入。每一步至少一项标准；断言针对该步完成并等待后台任务后的状态，不能用输入/旧消息冒充回复。预期的业务拒绝（例如锁定后 HTTP 400）可明确断言；未预期的 HTTP 错误、SSE 错误、模型 IO 失败均不能默认为通过。语义判定使用实际回复和该步业务证据，证据不足进入待复核。

例如：

```text
输入：
填写结论：写一本帮助别人的书
确认结论
发送消息：确认后还能聊吗
再聊聊

断言：
第1步：结论包含：写一本帮助别人的书
第2步：判定状态：done
第2步：组合状态：concluded
第3步：接口状态：400
第4步：组合状态：discussing
第4步：判定状态：none
```

业务起点必须保存 `workflow_seed`。从已有调试工作区预览时自动读取**同一访问范围内**的基本资料、前四维结论、实际已锁定的前置阶段、当前线程状态及锚点；保存前全部可检查和脱敏。手工起点的结构示例：

```json
{
  "completed_phases": ["values", "strengths", "interests", "purpose"],
  "basic_info": {"nickname": "虚构测试用户"},
  "conclusions": {"values": {"summary": "重视自由", "keywords": ["自由"]}},
  "thread_metadata": {},
  "anchor": {}
}
```

`completed_phases` 只能包含当前阶段之前的阶段，是声明的测试前置条件，不能用测试“通过”证明这些前置阶段刚刚被执行过。前四维的 `thread_metadata` 仅允许结论状态、草稿/终稿、反馈、完成状态、轮次和使命进度；不接受权限或产品配置。旧文字背景不会被猜测转换为业务状态；业务流程从结构化资料重新构建实际提示词。固定题库、历史与所选组合仍保存在对应原字段中。

执行器逐组创建全新源码副本、数据库、文件根和进程，以合成普通用户执行现有 simple-chat HTTP 路由；仅在该进程内替代登录身份和外部 LLM IO，不替换产品状态机、权限/归属门禁或提示词。业务回放不会连接正在服务用户的 dev/prod 后端。上下文仅覆盖所选线程/组合及声明的前置资料，**不是全量生产数据库/多组合报告恢复**；`选入终选` 只选该组合。每次重复丢弃执行数据，控制库和证据保留。

已覆盖自然出卡、pending 对话判定、手动请求/确认/再聊聊、沉淀确认与重判、真实 30 轮摘要阈值、终选锁定及报告 Markdown 预生成。报告仍受原审核规则约束，不自动批准，不生成/发布生产报告，不测试真实 PDF 渲染或付款。步骤结果保存请求、HTTP/SSE 响应、前后状态及该步每次模型请求。新增核心用例 `test-center-workflow` 位于固定用例目录；它使用受控模型回复验证真实业务接口，不能替代真实模型质量验收。

## 模型配置、预算与取消

Web 进程通过服务管理器设置 `TEST_CENTER_AI_CONFIG`（JSON，无密钥），例如按部署时核对过的场景填写：

```json
{
  "provider": "deepseek",
  "base_url": "https://api.deepseek.com/v1",
  "chat": {"model": "<线上前四阶段对应模型>", "thinking": true},
  "rumination": {"model": "<线上沉淀对应模型>", "thinking": true},
  "conclusion": {"model": "<结论对应模型>", "thinking": true},
  "report": {"model": "<报告对应模型>", "thinking": true},
  "unknown": {"model": "<未标记场景的锚点等后台任务模型>", "thinking": true}
}
```

示例中的模型是占位符，必须换成实际支持的模型。当前思考开关只支持 DeepSeek v4；其他兼容模型需关闭。历史回放只要求 chat/rumination；业务回放还需显式配置所涉及的 conclusion/report/unknown，缺失即报错，不继承产品凭据。worker 单独设置 `TEST_CENTER_AI_API_KEY`，仅显式 AI 子进程得到此凭据；不会继承业务 API 密钥、数据库或 `.env`。常规 API/UI 继续屏蔽真实外部操作。模型端点只能由服务配置指定，管理员用例文本不能改它。使用专门测试凭据与无生产资源权限的 worker 账号。

页面填写 `max_calls` 和 `max_tokens` 两项批次预算，或通过 `TEST_CENTER_AI_BUDGET` 配置默认上限；没有上限拒绝 AI 入队。上限由管理员决定，代码没有默认人民币额度。预估调用数 = 重复次数 × 各轮调用数之和（每轮 1 次目标回复，仅有适用于该轮的语义标准时追加 1 次判定）。历史回放没有自动重试。业务回放保留产品本身的重试，入队按步骤作保守估算，每次实际调用仍须预留成功才能发出；估算不是实际账单。编译产生 0 次模型调用。历史回放输出上限为 8192 token；业务回放沿用产品传入的上限（沉淀判定重试 8000/16000，报告最高 65536），并按该上限预留。

调用前事务性登记请求和保守 token 预留（文本 UTF-8 字节数、封装余量和最大输出），超预算不发出请求。成功收到完整 usage 后结算；这不是供应商 tokenizer 的精确预测。用量缺失、请求状态未知或实际用量超过预留时保留证据与额度、停止该批后续 AI 调用，不回退为通过。模型仍须正确执行自身输出限制；最终账单以供应商为准。

可选在 JSON 配置中同时加入 `input_price`、`output_price`（每百万 token）及 `currency`，报告按该批固定单价计算估算费用；未配置或用量不完整显示未知，缓存等供应商差别计费需人工核对。不会从历史模型价格表猜测费用。

取消后不发起后续请求；已发出的 HTTP 请求等待返回用量或超时（单次 90 秒），因此不会马上结束正在调用的 AI 用例。已发出的成本继续计入。外层超时/进程中断时账本保留已登记调用，不能因没有最后一份报告而当作免费或通过。

控制库和 AI 证据可能含管理员保存的上下文及模型回复；沿用超管鉴权，不提供公开链接。用例、草稿、上下文、调用与复核记录不随业务副本重置，不自动删除历史。
