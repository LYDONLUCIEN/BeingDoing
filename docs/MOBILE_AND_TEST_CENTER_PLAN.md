# 手机适配与管理员测试中心实施方案

日期：2026-10-14。基线：`clean@942849c`。

状态：Q1–Q15 已确认，工程默认值已接受；阶段一、二及第三阶段首版已实现并完成本地自动化验证，真机/外部渠道未验收，尚未部署；操作与限制见 [测试中心指南](TEST_CENTER.md)。决定见 [ADR-0027](adr/0027-test-center-fixed-cases-and-data-boundaries.md)，调查与讨论见 [原始讨论稿](MOBILE_AND_TEST_CENTER.md)。

## 1. 目标与交付次序

2026-10-14 后续确认：优先补齐测试中心功能，普通 PC 在 100% 缩放下的既有正常布局优先。高度不足不能自动把 guided 变成上下布局；宽度确实容纳不了内容时可收起组合栏，用户主动展开选择器时允许覆盖对话区，完成后收起。保留现有视觉、业务状态与输入草稿，避免为适配重做正常桌面界面。

同日首页补充决定：窄屏五张阶段卡改为紧凑纵向排列，卡片内部左图右文，完整保留标题与说明、配色、图标、圆角及选中效果；替代早期横滑方案。沿用首页既有 720px 窄屏范围，中等宽度三加二、普通桌面五张并排不变。其他页面横向区域仅调查讨论，不随首页一并调整；手机/电脑手动切换本轮不实施。

AI 同时支持独立单轮与固定连续多轮；同一脚本中承接前轮输入/回复及适用业务状态，脚本之间恢复独立起点。测试目的、逐轮输入和断言分别维护；生成与判定了解目的，但不据此更换被测提示词或暗改断言。完整业务转换需真实执行，单纯拼接聊天历史不能宣称覆盖结论确认、锁定或报告流程。

新增交付要求：从现行产品规范、开发文档与仍有效的历史功能/修复建立细粒度回归库，统一维护在 `test_agent/catalog/`；每项记录规则来源与执行入口，admin 可编辑、设核心、归档及一键运行。后续每次开发必须由开发者/代理同步创建或更新定义、真实脚本和变更关联，纳入贡献规范和开发手册。退役规则、冲突未定项及未实施产品不当作已确定断言。

用户端复用当前前端和素材完成手机主流程适配，admin 优先电脑。测试中心位于 dev，统一业务/API、UI 交互和 AI 对话测试；用例分核心与版本集合，可保存、编辑、选择运行、归档及查看证据。

| 阶段 | 交付内容 | 阶段完成条件 |
| --- | --- | --- |
| 一：测试底座＋手机首页 | 纠正假通过；隔离执行；核心/版本目录；开发登记；批跑与结果；首页/导航手机调整 | 真实允许/拒绝路径可验证，失败有证据；用例重复运行不污染数据；新开发用例可自动登记；手机首页及桌面回归验收 |
| 二：手机完整流程 | 注册、前四阶段聊天、沉淀、个人空间、报告下载与现有支付兼容 | 关键操作在手机可完成，键盘/滚动/切换不会遮挡或串会话；每次改动配套测试；现有渠道的能力与未通过项如实记录 |
| 三：管理员编写与 AI 回放 | 自然语言生成固定用例；分开编辑输入/断言；v4 保存点；真实 AI 判定、复核和费用控制 | admin 能描述、试跑、修订、保存并复跑用例；AI 结果只评价目标回复/业务状态，版本与上下文可追溯 |

微信支付和原生 App 不在本期；未来 App 可复用接口、素材和交互规则。Prompt Lab 跨提示词实验独立安排，不进入每次功能回归的多版本矩阵。

## 2. 管理员页面

沿用现有 admin 权限，后端验证实际管理员身份。建议新增独立测试中心入口，保留原沙箱和 Prompt Lab 的现有功能，通过链接接入。

页面按任务组织：

- **用例库**：核心/版本切换，按业务模块、测试类型、目标版本、状态筛选；显示名称、说明、最近结果与更新时间；支持勾选运行、加入/取消常驻、归档。
- **用例编辑**：分为前置状态、用户输入/操作步骤、断言标准、运行设置四部分。自然语言辅助生成草稿；显示不能理解/不能执行的步骤，不默默猜测合格条件。
- **版本验收**：显示 tag 或“最近 tag · 开发中”、具体提交、变化清单、关联用例和覆盖缺口。普通诊断可自由选用例；发布验收固定核心与该版必测清单，取消勾选不能让剩余项代表全部通过。
- **运行记录**：批次进度、取消、失败重跑、逐例及逐次结果、耗时、错误与证据；AI 展示实际输入/回复、断言理由、模型和费用；复核记录与自动判定并列。
- **数据与运行设置**：已导入的基准快照及时间、适用代码/数据版本、执行环境是否就绪、模型配置与批次预算。刷新的是业务基准，长期测试资产不被替换。

阶段一先交付已有固定用例的发现、运行和结果；完整自然语言编辑在阶段三交付，不用早期列表页面宣称最终测试中心完成。

用例编辑示例（规划，不是已保存的可执行用例）：

| 部分 | “流式回复期间不能新建会话” |
| --- | --- |
| 前置状态 | 测试账户处于前四阶段的指定线程；使用受控流式响应稳定呈现进行中状态 |
| 用户输入/操作 | 回复期间尝试新建会话；回复完成后再次新建 |
| 断言标准 | 进行中按钮禁用、不产生新建请求/记录；完成后可创建；旧回复仍归属原线程 |
| 运行设置 | UI 交互、受控模型响应、隔离场景数据；桌面与手机都执行 |

输入只表达用户做什么，断言只表达合格标准；更改任一部分可独立保存为新修订。

## 3. 用例、版本与自动登记

每个用例拥有稳定标识与不可变修订，记录名称、业务目标、类型、前置数据、输入/步骤、断言、执行能力、关联功能和适用版本。输入/断言独立编辑，任一修改均形成新修订。执行记录固定所使用的修订。

开发交付包含测试定义和变更清单，随代码维护。dev 加载新提交后幂等导入，已存在内容不重复创建；有人工修改时保留原内容，提供差异建议。admin 自建草稿与已确认修订放在独立测试控制存储中，可导出，不能混入将被刷新掉的业务副本。

自动生成以需求/验收标准、代码变化和既有用例共同为依据。无法确定预期的项登记为待澄清；缺用例的业务变更显式展示，不能仅靠“生成成功”或没有发现文件就判覆盖完整。第一版先覆盖明确的动作/断言目录，未知操作拒绝生成可运行版本。

版本规则：

1. 未打新 tag 的改动显示在“最近 tag · 开发中”，每次实际运行记录具体提交，未提交源码变更不能作为正式发布验收目标。
2. 新 tag 作为提测起点，归集它实际包含的开发改动及用例，固定版本清单；tag 之外或其他分支的变化不混入。
3. admin 选常驻即纳入核心集合；归档从未来清单移除，保留旧版本清单、用例修订和运行记录。核心集合调整也留记录。
4. 版本验收绑定具体构建、清单和运行配置。提测后修订用例或更换代码/配置，应形成新的验收记录，旧的通过结果不自动继承。
5. 发布使用 dev 验收过的同一构建。tag 自动化需要新接入，不能沿用旧 deploy.sh 的当前分支拉取行为来证明版本一致。

## 4. 执行与隔离

统一用例与报告模型，保留适合各类测试的执行器：业务/API 复用 pytest 及真实接口断言，UI 使用真实 Playwright，AI 使用固定上下文回放与专门判定。L1–L4 保留为内部技术信息，不作为 admin 的主要分类。

测试控制存储保存用例、版本清单、快照索引与结果；业务执行数据单独生成并丢弃。控制页面不随着测试账户注销或业务数据库恢复而失效。专属 worker 仅加载已登记、校验过的执行定义，不接受自然语言产生的任意 shell 或直接在主应用执行任意代码。

| 场景 | 起点与结束 |
| --- | --- |
| 局部 API/业务 | 最小固定数据、临时 DB/文件和必要内存状态；同例连续操作，结束丢弃 |
| 完整 UI/业务流程 | 独立账号、数据环境与浏览器上下文；多步连续推进，场景之间重置 |
| AI 效果 | 从同一保存点派生每次副本，固定输入、有效提示词/模型；证据另存，执行数据丢弃 |
| 存量兼容/迁移/全局统计 | 一致脱敏 DB＋data 及必要附件副本；先核对/演练适用迁移，再运行候选代码 |

隔离覆盖实际触达的 DB、JSON、索引、审计、缓存、限流和后台任务。不能只因 manager 换了文件根就认为全隔离；不能用被测删除接口充当唯一环境清理机制。

第一版 worker 默认串行，先确保独立性和取消/超时/清理可靠。普通 API/UI 测试对支付、邮件、OSS 和非目标 LLM 使用受控替身；真实模型只在明确标识的 AI 用例中调用，真实渠道联调单独验收。测试账户权限、访问地址和数据根由执行配置限定，不能从 admin 文本任意改变为生产目标。

## 5. 结果与 AI 判定

明确区分未运行、待澄清、运行中、通过、失败、待复核、环境错误和取消。模拟动作、执行不支持、断言未执行、初始化失败均不能计作通过。保留所有重跑记录，不用最终一次成功覆盖首次失败。

硬规则检查结构、状态、禁止行为或确定的文字；语义标准写明必达关注点与评价依据。判定器只检查目标轮次的 AI 回复及相关业务状态，用户输入/历史消息中出现期望文字不算命中。语义不明确进入待复核；管理员复核新增独立记录，不覆写自动结论。

默认每个 AI 输入用例调用一次，可选多次，每次从相同起点运行。报告展示每次结果与通过次数，不能把一次偶然成功显示成多次稳定通过；失败后重跑成功仍展示不稳定性，核心验收需明确处理。

固定并记录实际前后端构建、用例修订、数据快照、各场景最终提示词及来源、模型/参数、判定标准与执行器版本。环境变化时不能把前后结果合并成一个固定目标的验收结论。提示词实验不修改全局 current 来冒充任务级隔离。

运行前显示预计调用量、可估算费用和预算设置；停止任务后不再发起新调用，已发生调用与费用继续记录。预算检查包括生成、被测模型和模型判定的相关调用。没有可用配置或无法满足预算约束的任务明确未运行，不回退成假通过。

## 6. 生产样本与保留：已确认的默认值

已确认生产向测试单向、按需/发布前刷新、脱敏、外部操作隔离。首版具体建议：

1. 从按 [操作手册](OPERATIONS.md) 准备的一致快照制作脱敏测试基准，再导入 dev。测试按钮不自动停止生产或热复制正在变化的 DB/JSON；每次普通重跑只从已有基准派生副本。远端同步的账号/目录和生产取快照窗口在实际部署时核对。
2. 保持用户、订单、券、码、探索等关联和关键状态，替换邮箱/手机号等可识别资料，清除认证凭据、会话令牌、渠道/模型密钥与生产外部资源地址。长期 AI 回放样本由 admin 检查脱敏后的上下文和语义是否仍适合原断言，不能假设正则替换已经穷尽自由文本中的敏感内容。
3. 执行副本完成后丢弃；用例、版本清单、历史结果和管理员固定的上下文不自动删除。首版基准快照和证据也先提供容量展示与人工归档/清理，清理不能破坏仍被有效用例或审阅引用的内容。空间不足停止接收新任务并提示，不自动删除历史来腾空间。
4. 真实 AI 批次要求 admin 明确设置预算或使用已配置的上限，不擅自设定人民币额度；启动后显示实际用量。没有预算配置时仍可使用不调用真实模型的测试。

本次讨论和文档工作没有访问生产数据或服务器。本方案的确认用于开发边界，不把未核实的服务器状态当成已经可同步或已验收。

## 7. 手机验收建议

复用一套内容、接口与业务规则，布局按屏幕/容器适配，导航、聊天侧栏和沉淀视图按需要拆分。素材优先复用并裁切，保留 PNG 母版；遵循 [前端约束](DEVELOPMENT.md)。

建议自动检查 360、390、430px 手机宽度及平板/桌面代表宽度，使用 Chromium/WebKit 浏览器覆盖；实际 iPhone Safari、Android Chrome 对键盘、输入法、支付返回及 PDF 打开/保存做人工验收。浏览器模拟不冒充真机通过。

首批检查：首页无页面级横向溢出，文案/按钮不重叠，所有评价可访问，窄屏五张卡片沿页面纵向完整可读可点击，导航打开/关闭/跳转可用，素材加载与桌面布局无退化。卡片检查覆盖 720/721px、1050/1051px 边界、鼠标窄窗口与中英文长文案。

第二阶段检查：抽屉/侧栏不挤占手机聊天，键盘不遮输入与发送，流式期间禁用与切换规则保持，消息不串线程/组合；沉淀选择/填写/判断/终选可完成；注册验证和报告入口可访问，现有渠道与 PDF 下载按实际结果记录。报告 HTML 手机阅读属于额外功能，不自动扩大本期范围。

## 9. 验收与推进方式
