# 当前产品规则

核对基线 v1.8.0。规则冲突以较新已确认决策及实现一起核对；价格等运行配置未读取服务器值，不在此伪造线上事实。

## 探索与结论

- 主阶段为 values/strengths/interests/purpose/rumination。试用码在邮箱验证成功后幂等发放；老用户无码时 journeys 仅对已验证邮箱用户补发。试用仅 values、最多 10 条用户消息（internal 消息排除）；第 11 条及推进后续阶段以 402 拦截。只读不拦，调试豁免须走现有管理员/沙箱规则。
- 未验证邮箱禁止探索写操作；纯手机注册已关闭，历史手机号登录保留。问卷 nickname 缺省使用 users.username。
- 前四阶段选择结论并完成后锁定，页面二次确认。模型自然出卡无最小轮数限制；手动获取结论及其场景配置使用当前代码规则，不恢复历史 ≤10 轮强制压制。
- 沉淀用户界面仅 v4，v3 后端为兼容保留；不能按旧 ?v3=1 文档声称双界面仍上线。
- v4 新建组合进入空选点草稿，右侧输入锁定；「开始探索」成功后创建固定的一热爱+多优势组合，之后要换维度需新建组合。当前卡随当前组合展示，跳过可逆且保留文字。
- hypothesis 恒为用户填写的字符串。独立后台 AI 在确认快照上判定 balance_found/balance_fail_reason；修改卡片或新增对话使旧判断失效，分析时锁定该组合的卡与输入。失败可重试；未确认/已跳过卡不参与完成门槛，已确认卡须完成有效判断。不推荐只提示，不禁止终选。
- v4 不恢复旧 chips/tool/出卡双信号协议。咨询流程以现有 v4 prompt 原文为依据；`uidesign/prompt/rumination-v4new-prompt.md/rumination-v4-new.md` 是历史指定来源，干净克隆可能无该忽略目录，修改提示词时先取齐参考，不擅造内容。

## 激活、有效期与共享

- 套餐交付未绑定完整码：季度 1 个、年度 3 个，可自用/转赠/消耗升级。直接购买并不自动绑定；明确 upgrade_trial 购买意图走已实现的升级流程。
- ADR-0018 起新码从支付交付时起算有效期。存量 expires_at 为空的完整码保留首次使用起算兼容；试用码为空表示不限期。消耗升级继承被消耗码剩余有效期，码字符串与原探索保留。
- 免费续期每完整码首次过期可手动领取一次 7 天；付费延期当前 9.9 元/7 天，不可退。旧分档延期只供历史订单解释。
- 购买者与激活人分开记录。只有转赠码需要激活人向购买者授权报告，对话原文不能共享；自购自用不显示赠送者授权开关。

## 订单、折扣券、退款

- 一单最多一张券，金额为整数分，抵扣后实付最低为 0。付款与交付分离，取消订单须再次查渠道防止已付款却被取消；这些状态机不能在清理中简化。
- 单次券可绑定用户；多次券 max_uses>1 为流通券，每用户每券一次，邮件券池跳过多次券。用 coupon_redemptions 记录每次锁定/使用/释放/退款，保留单次券的历史单槽字段。
- 新券有期限（后台默认回退 90 天），有停用和作废概念；过期为派生态。新格式 Q- + 8 位；激活码 OPENLIFE-XXXX-XXXX-XXXX。存量裸码继续精确匹配，归一化按输入框类型区分，不能把券当激活码。
- 2026-10-05 起用户可申请全退/部分退，管理员审批或代录，统一退款单审计。套餐按未用码对应明细行退款并作废相应码；咨询仅未预约可退，延期不可退。0 元单仍走审核/核销但跳过渠道调用。部分退不退券，全退满足条件才返还券。
- 支付协议先同意再创建支付订单；继续支付沿用原单。等待支付关闭弹窗保留继续/离开/取消三个动作，0 元交付仍走业务幂等。

权威详细设计：[退款定稿](../wiki/开发文档/10-05/订单系统退款设计.md)、[多次券定稿](../wiki/开发文档/10-06/优惠券多次核销与码格式区分-设计定稿.md)。

## 报告

- 终选提交完成五阶段后开始审核并预生成，report 页查询是兜底触发。审核默认固定 24 小时自动批复（历史 pending 不回溯）；用户能否下载需同时核对完成度、审核和归属。
- 报告重新生成是 LLM 生成新 Markdown；重新渲染只是现有 Markdown 出新版 PDF。用户问题走复核申请，force 重新生成限管理员，不能从旧接口绕过。
- 唯一 PDF 引擎为 src/report-renderer 的 xunlu（ADR-0021），无 WeasyPrint 切换/兜底。缓存 Markdown，下载时生成 PDF bytes；母版只读。首次分配签名持久化，重渲染保持同一签名。
- 后处理按章节做确定性规范化和信件压缩，失败保留原文。修版式不应触发重新消耗 LLM 生成报告。
