# 当前产品规则

核对 v1.8.0 + clean。规则变更原因与约束见 [架构与开发决策](DECISIONS.md)。规则冲突以较新已确认决策及实现一起核对；价格等运行配置未读取服务器值，不在此伪造线上事实。

## 探索与结论

- 主阶段为 values/strengths/interests/purpose/rumination。试用码在注册/绑定/验证任一「邮箱已验证」时点幂等发放（ADR-0026 起新注册落库即已验证，注册完成即发）；老用户无码时 journeys 仅对已验证邮箱用户补发。试用仅 values、最多 10 条用户消息（internal 消息排除）；第 11 条及推进后续阶段以 402 拦截。只读不拦，调试豁免须走现有管理员/沙箱规则。
- 未验证邮箱禁止探索写操作；纯手机注册已关闭。ADR-0026 起注册邮箱验证前置（验证码+链接双形态，凭 ticket 建号），不再产生新的未验证账号；手机+密码登录仅作纯手机老账号进入强制绑定邮箱流程的认证手段（硬门禁受限 token），「历史手机号登录保留」条款已废止。问卷 nickname 缺省使用 users.username。
- 前四阶段选择结论并完成后锁定，页面二次确认。模型自然出卡无最小轮数限制；手动获取结论入口在有用户消息、无待表态卡且线程未完成等条件下显示，点击先 judge，通过后才生成；不恢复历史 ≤10 轮强制压制或点击即出卡。
- 沉淀前后端只运行 v4；旧七步/矩阵接口与 A/B 分流已退役。历史记录通过有权限的只读入口保留，不能按旧文档恢复双版本，也不把旧矩阵转换为用户终选。
- v3 已定稿且旧 Markdown 报告可读的历史报告，经后端严格派生标记确认后直接收口到报告页；仅前四阶段已选定、旧 rumination 会话锁定、原生 v3 进度与报告缓存齐全，且完全没有 combo、active 组合、终选草稿/提交等 v4 实质数据时才成立。任一条件缺失或读取失败都进入 v4 原流程；这不是数据迁移，也不回填终选（ADR-0028）。
- v4 默认引导工作区无激活组合时先展示新建引导，不自动展开选择器（手机先停留在对话引导）；左侧或对话引导卡的「新建组合」均只进入空选点草稿并打开对应选择面板，对话输入保持锁定；「开始探索」成功后创建固定的一热爱+多优势组合，之后要换维度需新建组合。当前卡随当前组合展示，跳过可逆且保留文字。
- hypothesis 恒为用户填写的字符串。独立后台 AI 在确认快照上判定 balance_found/balance_fail_reason；修改卡片或新增对话使旧判断失效，分析时锁定该组合的卡与输入。失败可重试；未确认/已跳过卡不参与完成门槛，已确认卡须完成有效判断。不推荐只提示，不禁止终选。
- v4 不恢复旧 chips/tool/出卡双信号协议。咨询流程以现有 v4 prompt 原文为依据；`uidesign/prompt/rumination-v4new-prompt.md/rumination-v4-new.md` 是历史指定来源，干净克隆可能无该忽略目录，修改提示词时先取齐参考，不擅造内容。

## 首页首屏

- 五张探索阶段卡默认均不选中，不自动随机高亮。鼠标悬停只显示临时选中态，离开该卡立即清除；点击或键盘形成的选中不被悬停覆盖，悬停结束后恢复该选中。
- 顶部场景图位于阶段卡下层；图片下边缘通过透明渐隐、渐进模糊和白色衔接消除硬边，避免被误认为图片尚未加载完整。

## 激活、有效期与共享

- 套餐交付未绑定完整码：季度 1 个、年度 3 个，可自用/转赠/消耗升级。直接购买并不自动绑定；明确 upgrade_trial 购买意图走已实现的升级流程。
- 购买方案对外统一展示为免费版、启程版、远航版；个人空间购买入口复用同一名称，普通套餐购买弹窗默认选中启程版。内部 `quarterly_package` / `annual_package` 商品类型保持不变。
- ADR-0018 起新码从支付交付时起算有效期。存量 expires_at 为空的完整码保留首次使用起算兼容；试用码为空表示不限期。消耗升级继承被消耗码剩余有效期，码字符串与原探索保留。
- 免费续期每完整码首次过期可手动领取一次 7 天；付费延期当前 9.9 元/7 天，不可退。旧分档延期只供历史订单解释。
- 购买者与激活人分开记录。只有转赠码需要激活人向购买者授权报告，对话原文不能共享；自购自用不显示赠送者授权开关。

## 账户与设置

- 2026-10-18 起设置页暂时隐藏「注销账户」入口；注销、30 天恢复和到期清理功能保留。UI 隐藏不替代后端确认与权限校验。

## 订单、折扣券、退款

- 一单最多一张券，金额为整数分，抵扣后实付最低为 0。付款与交付分离，取消订单须再次查渠道防止已付款却被取消；这些状态机不能在清理中简化。
- 单次券可绑定用户；多次券 max_uses>1 为流通券，每用户每券一次，邮件券池跳过多次券。用 coupon_redemptions 记录每次锁定/使用/释放/退款，保留单次券的历史单槽字段。
- 新券有期限（后台默认回退 90 天），有停用和作废概念；过期为派生态。新格式 Q- + 8 位；激活码 OPENLIFE-XXXX-XXXX-XXXX。存量裸码继续精确匹配，归一化按输入框类型区分，不能把券当激活码。
- 2026-10-05 起用户可申请全退/部分退，管理员审批或代录，统一退款单审计。套餐按码对应明细行退款并作废相应码；延期不可退。0 元单仍走审核/核销但跳过渠道调用。部分退不退券，全退满足条件才返还券。2026-10-13 起申请与审批不再以「激活码已被使用/咨询已预约」拦截：申请照单全收并通知管理员，审批详情展示行实时状态，由管理员人工判断（可强制批准，批准后对应码强制作废、预约取消）。2026-10-18 起用户端订单记录不再展示自助「申请退款」按钮，后端退款申请、审批与执行能力保留。
- 2026-10-18 起 admin 可按订单 ID 或商户订单号主动代录退款。内部 `paid` 订单可全额退款；本地仍为 `pending` 的订单必须先经支付渠道确认已付款且金额一致，创建与审批时各核实一次，且仅允许全额退款，防止未交付订单部分退款后既不能交付也不能再退。退款申请被驳回或撤回后，订单回到 `pending`，恢复对账补交付。
- 季度套餐允许 admin 协商部分退款：必须选择唯一未退款明细行，退款金额不得超过该行分摊实付；批准后该行标记已退款并防止重复退款。用户侧自助入口不因此恢复。
- 退款批准后默认作废已选激活码；admin 在审批时可明确选择保留激活码。选择保留时退款行仍标记已退款，防止同一明细重复退款。
- 支付协议先同意再创建支付订单；继续支付沿用原单。等待支付关闭弹窗保留继续/离开/取消三个动作，0 元交付仍走业务幂等。

历史设计依据：[退款定稿](../wiki/历史开发记录/10-05/订单系统退款设计.md)、[多次券定稿](../wiki/历史开发记录/10-06/优惠券多次核销与码格式区分-设计定稿.md)。原文保留详细取舍；适用范围按本页、字段字典及后续明确决定读取，历史部署声明不代替当前验证。

## 报告

- 终选提交完成五阶段后开始审核并预生成，report 页查询是兜底触发。审核默认固定 24 小时自动批复（历史 pending 不回溯）；用户能否下载需同时核对完成度、审核和归属。
- 报告重新生成是 LLM 生成新 Markdown；重新渲染只是现有 Markdown 出新版 PDF。用户问题走复核申请，force 重新生成限管理员，不能从旧接口绕过。
- 唯一 PDF 引擎为 src/report-renderer 的 xunlu（ADR-0021），无 WeasyPrint 切换/兜底。缓存 Markdown，下载时生成 PDF bytes；母版只读。首次分配签名持久化，重渲染保持同一签名。
- 后处理按章节做确定性规范化和信件压缩，失败保留原文。修版式不应触发重新消耗 LLM 生成报告。
