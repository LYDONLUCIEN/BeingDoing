## 代码事实：测试基础与可信度

已有大量后端 pytest；[管理员沙箱页面](../src/frontend/app/(main)/admin/sandboxes/page.tsx) 已有保存点、导出场景、多选批跑、失败重跑、进度、取消和历史。[Prompt Lab](../src/frontend/app/(main)/admin/prompt-lab/page.tsx) 有提示词版本能力。`test_agent` 有 Playwright、固定句式解析和 AI 用户模拟脚手架。

这些能力尚未形成统一的三类用例库、自然语言编辑器和持续集成门禁。调查没有发现仓库内已接通的 CI 配置；这不证明外部 CI 一定不存在。

必须先解决的缺口：

1. **模拟成功不能作为真实通过。** [LocalActionExecutor](../test_agent/core/bdd/executor.py) 的点击、文本和 DOM 断言直接返回 pass；[业务适配器](../test_agent/adapters/beingdoing/adapter.py) 的“不重复追问”“阶段符合预期”也直接 pass。部分 Playwright 未支持动作会回退本地模式，nightly profile 默认 L3/L4 使用 local/stub。历史绿报告不能据此证明真实 UI/AI 效果已通过。
2. **用户输入和 AI 预期混用。** [保存点导出](../src/backend/app/utils/admin_savepoints.py) 将 `expected_hint` 同时写成用户消息和期望文本；[浏览器 runner](../test_agent/l2/playwright_runner.mjs) 在全页 body 搜索，可能命中刚发送的用户消息。建议拆开用户输入与评价标准，明确只检查目标 AI 回复及相关业务状态。
3. **v4 保存点不足。** 现有保存点主要定位 `phase__thread_id.json`；现行沉淀 combo 存在 `rumination_v4_progress.json`，未发现完整的 combo 内部快照/恢复实现。
4. **业务交互断言不够完整。** 禁用、跳转、拦截、请求不得发出、流式期间互斥等需要真实执行与断言，不能仅检查页面有某段文字。
5. **执行完成与质量通过需要分开。** CLI 回放主要按是否抛异常计数；pytest 回放中的 metadata 和逐步断言更适合作为扩展基础。
6. **保存与版本边界待设计。** 当前保存点导出会写源码中的 fixture/YAML/索引，尚缺完整的草稿、试跑、版本发布和代码版本关联机制。

[验证记录](TESTING.md) 最新第五轮记录为 **899 passed、32 failed**，且未做浏览器端验收。这是仓库既有记录，不是本轮复测结果。新测试中心应分别展示通过、失败、未运行、环境错误、模拟执行和不稳定重试；已有失败不能隐藏成全绿。

建议的用例编写流程：

> 自然语言描述 → 明确前置条件/输入/操作/预期 → 生成结构化草稿 → 试跑与检查 → 保存固定版本 → 选择套件运行 → 查看逐项证据。

建议第一版使用受支持的动作与断言目录。无法理解或尚未支持的步骤明确提示，不自动当作通过；管理员无需编写代码。固定用例由受限执行器运行，不把任意生成代码直接交给生产应用进程执行。API、真实浏览器和真实模型分别使用合适的执行方式，统一展示结果。

“每次新功能自动有测试”可落实为开发交付要求、测试登记和 CI 检查；系统可以辅助生成与自动发现用例，但无法在没有验收规则的情况下保证生成了完整正确的业务测试。核心发布套件与管理员临时选择的诊断套件需要分别定义。

AI 效果采用“冻结上下文＋用户输入＋硬规则＋语义评分＋必要人工复核”的已确认方向。硬规则验证结构/状态/禁止行为，语义标准描述关注点；精确文案仅用于确需逐字一致的内容。**功能回归只针对实际使用的一套提示词**，跨提示词比较仅归 Prompt Lab。每轮记录代码、数据快照、模型、参数、实际生效提示词和评分标准版本；Q13 已确认默认每用例 1 次，可手动重复。

## 代码事实：生产数据复制

当前文档中的 dev 是候选版本测试服务器，prod 是生产服务器；`data/test/simple` 另指管理员调试数据根。设置 `APP_ENV=test` 不代表整台服务和所有外部副作用已隔离。见 [操作手册](OPERATIONS.md) 与 [激活码数据根](../src/backend/app/utils/simple_activation_manager.py)。

账户/交易在 SQLite，探索/激活码/报告有 JSON 主源，附件还涉及 OSS；DB 和 JSON 尚无统一事务。现行操作手册的一致快照要求停全部写入，使用 SQLite Backup API 并复制 data，OSS 另行纳入。尚未发现完整 prod→dev 同步流水线。

[应用启动任务](../src/backend/app/main.py) 包括账户清理、支付关单/对账、报告审核和到期邮件。退款、SMTP、OSS 删除按配置调用外部系统；数据库还可能包含 DB-first 的模型配置。**单向复制数据库并不能保证测试不会影响真实渠道、用户邮箱或生产对象存储。** 不能把生产环境文件/凭据原样恢复到测试环境。

建议先采用按需/发布前刷新的一致脱敏快照，再从固定快照派生可重置的测试副本。测试用例、已保存的 AI 上下文和运行记录单独存放，刷新业务数据不会覆盖它们。支付、邮件、存储、后台任务与模型调用分别设测试环境边界；真实渠道联调独立运行。

固定合成数据适合每次必跑的可重复回归；脱敏生产样本补充历史兼容、迁移与规模验证。真实对话如何脱敏、哪些上下文需要保真，应进一步讨论，不能假设删除姓名就完成脱敏。

生产副本可以增加历史状态覆盖，但发布仍需核对代码版本、迁移、依赖、配置、构建、代理/SSE、浏览器、并发及第三方服务。测试通过提高上线信心，不构成生产必过的保证。

## 第二轮事实补充（同一基线，只读核对）

- **tag 暂未驱动测试登记**：[旧部署脚本](../deploy.sh) 只拉取当前分支；[现行操作手册](OPERATIONS.md) 要求 dev 验收候选 SHA、prod 部署相同 SHA。保存点场景索引没有完整的来源 tag、比较基准、常驻/版本状态及审核记录，需新增这一层能力。
- **Prompt Lab 的“绑定”会跟随当前版本**：[Lab 工具](../src/backend/app/utils/admin_prompt_lab.py) 保存版本即更新 profile 当前版本，绑定只记录 profile；后续对话可读到新版本。[回放 CLI](../src/backend/scripts/replay_simple_chat.py) 的指定版本操作还会修改全局 current，不可直接作为并行提示词比较的隔离机制。
- **实际提示词不是一个全局模板**：普通用户走各场景的实际代码模板和运行时上下文，Lab 覆盖仅适用授权调试场景，v4 暂无同样覆盖。模型参数也有热更新入口。发布回归应固定各场景实际生效的配置，并从真实请求组装结果留证；不能只记录编辑器预览或一个 tag。
- **创建后再删除不等于恢复原状**：[折扣券服务](../src/backend/app/services/coupon_service.py) 的删除是作废，释放仍保留归属/核销历史；[激活码管理器](../src/backend/app/utils/simple_activation_manager.py) 软删、恢复和永久删除涉及索引、回收站、报告目录与审计。[券测试](../test/backend/test_coupon_multi_use.py) 与 [支付测试](../test/backend/test_payment_service.py) 已有每例临时 DB、文件根和外部服务替身的可复用模式，但不能假定所有既有测试已统一隔离。
- **现有保存点不等于全环境快照**：UI load 会原地恢复同一调试激活码的报告目录并更新共享索引；replay 有独立运行目录，但都未证明覆盖全部数据库、审计、限流或后台状态。两个保存点若属于同一报告，现有按保存点 ID 的互斥不足以防并行覆盖。应在隔离执行环境中补齐边界。

以上支持“按涉及状态选择最小恢复范围”的建议：局部 API 用例可使用临时数据，完整流程/历史兼容使用快照副本。测试类型与恢复策略是两个维度，直接调用接口不意味着零副作用。

### Q12 开发登记与新 tag 归集

将“一次开发”落到一次功能/缺陷修复交付：开发时同步生成或更新用例定义、断言和变更清单，随代码保存；dev 加载该提交后自动登记为待测。已有同一用例按修订更新，不重复新建；admin 修改过的内容保留，冲突形成建议。

未打新 tag 时显示为“最近 tag · 开发中”，具体运行仍记录实际提交。新 tag 建立时，将它所包含提交关联的开发增量归集为该 tag 的版本测试清单，并固定该次提测的用例修订；较晚或其他分支的变化不混入。已有运行历史及原 tag 指向保留不动。

例子仅为说明，不创建真实 tag：`v1.8.0 · 开发中` 先积累功能 A/B 用例；后续 `v1.9.0` 若包含 A/B，则形成该版提测清单；旧版历史继续可查。

### Q13 真实 AI 调用默认力度

真实 AI 对话回归默认每个输入用例运行 1 次；admin 可选重复次数，每次从相同起点派生独立副本，保留所有输出与结果。一次通过只代表该次观察，不能当作已经证明稳定性。

执行前展示目标模型、场景/轮次数、预计调用数量和可用时的费用估算；支持批次预算上限、取消与已发生费用记录。实际估算依上下文长度和模型费率，不保证精确。普通业务/UI 逻辑回归默认使用受控模型响应；验证真实 AI 输出的用例单独清晰标识，不把替身成功计为真实模型通过。

### Q14 交付顺序
